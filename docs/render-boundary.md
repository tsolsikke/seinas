# 共通のレンダラーとバックエンドの境界

Seinasは、次の3つの部分に分かれています。

| 部分 | 場所 | 役割 |
| --- | --- | --- |
| フロントエンド | `crates/seinas-frontend` | Waylandのクライアントの要求を受け、描く要素を並べる |
| 共通のレンダラー | `crates/seinas-render` | 並んだ要素を、1枚の絵に合成する |
| バックエンド | `crates/seinas/src/parent.rs` | できた絵を、出力先へ出す |

この文書は、共通のレンダラーとバックエンドのあいだの決まりをまとめたものです。
バックエンドは2つあります。親のWaylandにウィンドウを開く「入れ子」(`crates/seinas/src/parent.rs`)と、fbdevの画面へ present するもの(`crates/seinas-fbdev`、`docs/fbdev.md`)です。どちらも同じ決まりに従います。

## 描画結果の形式

共通のレンダラーは、結果を `FrameView` として返します。

- ピクセルの形式は `Xrgb8888` の1種類です。1ピクセルは32ビットで、メモリー上にはB、G、R、Xの順に並びます。Xの8ビットに意味はありません。
- 行は上から下へ、ピクセルは左から右へ並びます。
- 1行のバイト数(`stride`)は「幅×4」以上で、ちょうどとは限りません。行の後ろに余りがあることがあります。
- バックエンドは、`row(y)` で1行ずつ読むか、`copy_to` で自分のバッファへまとめてコピーします。どちらも余りの部分には触れません。
- 大きさは `Painter` を作るときに決まり、途中では変わりません。
- 描けない要素があっても、失敗にはしません。ほかの要素は描き、描けなかった数を `failed_elements()` で伝えます。バックエンドは、絵をそのまま出してかまいません。

## バッファの所有権と寿命

バッファは3種類あり、持ち主がそれぞれ違います。

| バッファ | 持ち主 | 寿命 |
| --- | --- | --- |
| キャンバス(レンダーターゲット) | 共通のレンダラー(`Painter`) | `Painter` と同じ |
| 表示用のバッファ | バックエンド | バックエンドが決める |
| クライアントのバッファ | クライアント(フロントエンドが参照を預かる) | クライアントが壊すまで |

- `FrameView` は、キャンバスを読むためのビューです。ピクセルは `Painter` が持ったままで、`FrameView` が生きている間は次の `paint` を呼べません(コンパイラが止めます)。
- バックエンドは、`FrameView` の中身を自分の表示用のバッファへコピーします。キャンバスそのものを出力先へ渡すことはしません。こうしておくと、出力先が前の絵をまだ使っている間でも、キャンバスには次の絵を描けます。
- 表示用のバッファの使い回しは、バックエンドの責任です。入れ子のバックエンドは、親がまだ使っているバッファには書かず、空いているバッファを取り直します。
- 描く要素は、呼ぶ側が `paint` のたびに作って渡します。共通のレンダラーは、`paint` の間だけ要素を借り、覚えておきません。

## 描画と表示のタイミングの分け方

- 共通のレンダラーは、呼ばれたときに1枚を描いて返すだけです。時計もイベントも持たず、いつ描くかは決めません。
- いつ描くかは、状態をまとめる側(`crates/seinas/src/main.rs` と `crates/seinas-standalone/src/main.rs`)が決めます。「再描画が要る」ことと「バックエンドがいま出せる」ことの両方がそろったときに `paint` を呼びます。
- いつ出せるかは、バックエンドが決めます。入れ子のバックエンドは、親の最初のconfigureを待ち、絵を出した後は親のframeコールバックが届くまで次を出しません。fbdevのバックエンドでは、垂直同期やタイマーがこれに当たります。
- 絵を出し終えたら、フロントエンドがクライアントへframeコールバックを返します。クライアントは、その通知を受けて次の絵を描きます。

## フロントエンドを持たない構成

`seinas-render` は、Smithayの `wayland_frontend` の機能を使っていません。そのため、`seinas-render` だけを使うプログラムは、Waylandのソケットを開かず、共有メモリー(wl_shm)の実装も含まずに組み立てられます。

- 描く要素は `RenderElement` であれば何でもよく、クライアントの画面である必要はありません。
- 要素が1つも無ければ、背景だけの絵になります。
- `crates/seinas-render/tests/render_only.rs` が、この構成でスレッドやシグナルのハンドラーが増えないことを確かめています。

ただし、同じビルドの中に `wayland_frontend` を使うクレートがあると、Cargoは機能を1つにまとめます。
フロントエンドを含まない実行ファイルを作るときは、`cargo build -p <そのクレート>` のように、対象を絞ってビルドしてください。
