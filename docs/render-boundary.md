# 共通の描画と裏側の境界

Seinasは、次の3つの部分に分かれています。

| 部分 | 場所 | 役割 |
| --- | --- | --- |
| 受け口 | `crates/seinas-frontend` | Waylandのクライアントの要求を受け、描く要素を並べる |
| 共通の描画 | `crates/seinas-render` | 並んだ要素を、1枚の絵に合成する |
| 裏側 | `crates/seinas/src/parent.rs` | できた絵を、表示先へ出す |

この文書は、共通の描画と裏側のあいだの決まりをまとめたものです。
裏側は2つあります。親のWaylandにウィンドウを開く「入れ子」(`crates/seinas/src/parent.rs`)と、fbdevの画面へ出すもの(`crates/seinas-fbdev`、`docs/fbdev.md`)です。どちらも同じ決まりに従います。

## 描画結果の形式

共通の描画は、結果を `FrameView` として返します。

- 画素の形式は `Xrgb8888` の1種類です。1画素は32ビットで、メモリー上にはB、G、R、Xの順に並びます。Xの8ビットに意味はありません。
- 行は上から下へ、画素は左から右へ並びます。
- 1行のバイト数(`stride`)は「幅×4」以上で、ちょうどとは限りません。行の後ろに余りがあることがあります。
- 裏側は、`row(y)` で1行ずつ読むか、`copy_to` で自分のバッファへまとめて写します。どちらも余りの部分には触れません。
- 大きさは `Painter` を作るときに決まり、途中では変わりません。
- 描けない要素があっても、失敗にはしません。ほかの要素は描き、描けなかった数を `failed_elements()` で伝えます。裏側は、絵をそのまま出してかまいません。

## バッファの所有権と寿命

バッファは3種類あり、持ち主がそれぞれ違います。

| バッファ | 持ち主 | 寿命 |
| --- | --- | --- |
| キャンバス(合成先) | 共通の描画(`Painter`) | `Painter` と同じ |
| 表示用のバッファ | 裏側 | 裏側が決める |
| クライアントのバッファ | クライアント(受け口が参照を預かる) | クライアントが壊すまで |

- `FrameView` は、キャンバスを読むための窓です。画素は `Painter` が持ったままで、`FrameView` が生きている間は次の `paint` を呼べません(コンパイラが止めます)。
- 裏側は、`FrameView` の中身を自分の表示用のバッファへ写します。キャンバスそのものを表示先へ渡すことはしません。こうしておくと、表示先が前の絵をまだ使っている間でも、キャンバスには次の絵を描けます。
- 表示用のバッファの使い回しは、裏側の責任です。入れ子の裏側は、親がまだ使っているバッファには書かず、空いているバッファを取り直します。
- 描く要素は、呼ぶ側が `paint` のたびに作って渡します。共通の描画は、`paint` の間だけ要素を借り、覚えておきません。

## 描画と表示のタイミングの分け方

- 共通の描画は、呼ばれたときに1枚を描いて返すだけです。時計もイベントも持たず、いつ描くかは決めません。
- いつ描くかは、状態をまとめる側(`crates/seinas/src/main.rs` と `crates/seinas-standalone/src/main.rs`)が決めます。「描き直しが要る」ことと「裏側がいま出せる」ことの両方がそろったときに `paint` を呼びます。
- いつ出せるかは、裏側が決めます。入れ子の裏側は、親の最初のconfigureを待ち、絵を出した後は親のframeコールバックが届くまで次を出しません。fbdevの裏側では、垂直同期やタイマーがこれに当たります。
- 絵を出し終えたら、受け口がクライアントへframeコールバックを返します。クライアントは、それを合図に次の絵を描きます。

## 受け口を持たない構成

`seinas-render` は、Smithayの `wayland_frontend` の機能を使っていません。そのため、`seinas-render` だけを使うプログラムは、Waylandのソケットを開かず、共有メモリー(wl_shm)の実装も含まずに組み立てられます。

- 描く要素は `RenderElement` であれば何でもよく、クライアントの画面である必要はありません。
- 要素が1つも無ければ、背景だけの絵になります。
- `crates/seinas-render/tests/render_only.rs` が、この構成でスレッドやシグナルの受け口が増えないことを確かめています。

ただし、同じビルドの中に `wayland_frontend` を使うクレートがあると、Cargoは機能を1つにまとめます。
受け口を含まない実行ファイルを作るときは、`cargo build -p <そのクレート>` のように、対象を絞ってビルドしてください。
