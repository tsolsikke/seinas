# デスクトップの見た目の仕様(タスクバー・トーチ・時計・ウィンドウの枠とタイトルバー)

## 状態

案(2026-10-26)。運用者の決定と、仮に決めて進める値(後で変えやすいように、テーマのトークン `crates/seinas-theme` の 1 か所にまとめる)と、未決のものを分けて書く。

## 目標の見た目

- 運用者が GPT で作った見本の画像(ダーク、薄いタスクバー。1672x941)を、目標の見た目とする(2026-10-26 の決定)。見本の画像は運用者が持ち、リポジトリには入れていない。
- 見本の画像は生成したもので、寸法は正確ではない。下の「比べた値」の「見本の画像」は、画像のピクセルから読んだ値(1920x1080 に直したものも並べる)で、仕様ではない。
- 見本の画像と運用者の決定が合わない所は、決定を採る(下の各節の「決定」)。
- 対象は、タスクバー・トーチ・時計・常駐タスクと IME の表示・ウィンドウの枠・タイトルバーとボタン。見本の画像の中のアプリの中身(ファイルの管理、端末)は対象にしない。
- Microsoft のアイコン・フォント(Segoe など)・画像は使わず、コピーもしない。アイコンと記号は、自作か、ライセンスの合うもの(出典とライセンスを書く)にする。

## 運用者の決定

- 2026-10-07:Windows 11 に近い操作感を基本に、Windows と macOS の良いところを採る。ウィンドウは重ねる型。スタートボタンにあたるものを「トーチ」と呼ぶ。タスクバーは既定で下に置き、上下左右へ動かせる。トーチとタスクのまとまりは既定で中央揃え(左寄せも選べる)。時計・常駐タスク・IME の表示は、横置きでは右側。利用者が好きなフォントを使える。
- 2026-10-26:見本の画像を目標の見た目とする。ダークを既定にする。トーチに、起動中・前面の線や点を付けない。タスクバーは薄く(高さ 40)。見本の画像と決定が合わない所は、決定を優先する。
- 前からの決まり:描画は CPU(pixman)で行い、GL・EGL を必須にしない。文字は 14 px 以上。壁紙は同梱の運用者の画像(`docs/wallpaper.md`)。

## 部品ごとの決まり

### タスクバー

| 分け | 中身 |
| --- | --- |
| 決定 | 既定で下。高さ 40。トーチとタスクのまとまりは中央揃え。並びはトーチ → タスク。時計などは右側。ダーク |
| 仮の値 | 地 `#0F1B2F`、上の端に 1 px の線 `#21304A`。アイコン 24、当たりの範囲 36×36(縦は中央)、アイコンの間隔は中心から中心で 40(比べる形:48)。ポインターが乗ったときの地 `#1D2A40`、押したときの地 `#24344D`(当たりの範囲を、角の丸み 4 で塗る) |
| 未決 | 上下左右へ動かす作り(今は下だけ)、左寄せの切り替え、入りきらないときの扱い(今は、間隔を 36 まで詰め、それでも入らないタスクは出さない。あふれた分を別の一覧にまとめる形は後で)、ウィンドウごとの名前の出し方(ツールチップ) |

### トーチ

| 分け | 中身 |
| --- | --- |
| 決定 | まとまりの先頭。起動中・前面の線や点を付けない |
| 仮の値 | 壁紙の火に合わせた、簡単な炎の絵柄(自作。描画のコードで描く。外の炎はアクセントの色、内の炎は明るい黄)。ポインターが乗った・押したは、タスクと同じ地の色で示す。メニューはまだ無いので、押したらログに 1 行出すだけ |
| 未決 | アイコンの最終形(運用者が決める)、トーチのメニュー |

### タスク(開いているウィンドウ)

| 分け | 中身 |
| --- | --- |
| 決定 | 前面と背面を、色だけでなく形でも分ける。前面にしても、並びの順を変えない(ウィンドウを出した順のまま) |
| 仮の値 | 前面:アイコンの真下に、アクセントの色の短い線(長さ 24、太さ 3。下の端から 3 上)。背面(最小化したものを含む):小さな点(径 5、`#8190AB`)。ボタンを押したときの動き(戻す・前面にする・最小化する)は、今までと同じ(`docs/taskbar.md`) |
| 未決 | 同じアプリのウィンドウをまとめるか |

### アプリのアイコン(タスクとタイトルバー)

| 分け | 中身 |
| --- | --- |
| 仮の値 | app_id → `.desktop` のファイル(`$XDG_DATA_HOME/applications`、`$XDG_DATA_DIRS` の各々の `applications`)の `Icon` → アイコンのテーマ(freedesktop の決まりの hicolor。`<データの置き場>/icons/hicolor/<大きさ>x<大きさ>/apps/<名前>.png`。それに `/usr/share/pixmaps`)→ 見つからなければ既定のアイコン(角の丸い四角に、タイトルバーの線を引いた自作の絵柄)。PNG だけを読む(SVG は読まない。そのための依存を入れない)。大きさが違えば、縮めて使う |
| 未決 | PNG を読むか:PNG を読むクレート(png)は、壁紙のほかに入れない決まり(CI と pre-push の check-deps。壁紙を足したときに決めた)があり、タスクバーとコンポジタで読むには、その決まりを変えるか、別の形(自前の読み方、壁紙のように別のプロセスで読む、など)が要る。決まるまでは、探して見つけても読まず、既定のアイコンを出す。ZeikOS の上でのアイコンの置き場 |

### 時計

| 分け | 中身 |
| --- | --- |
| 決定 | 右側に置く。文字は 14 px 以上 |
| 仮の値 | 14 px の 2 段(上に時刻 `HH:MM`、下に日付 `YYYY/MM/DD`)。40 の高さに収まらなければ、行の間を詰める → 日付を短くする(`MM/DD`)→ 1 段(時刻だけ)の順に試す(どれを採ったかは、`docs/taskbar.md` に書く)。時刻が取れないときは `--:--` の 1 段 |

### 右側の常駐タスク・音量・IME の表示

| 分け | 中身 |
| --- | --- |
| 決定 | 横置きでは右側 |
| 仮の値 | `^`(常駐タスク)・音量・あ(IME)は、中身のあるときだけ出す。今は中身が無いので、時計と日付だけを出す(偽の表示を出さない)。時計との間の区切りの線(`#2F3D52`、1 px)は、左に何か出るときだけ |
| 未決 | 常駐タスクの仕組み(トレイの互換を含めるか)、IME の状態(あ/A)を届ける道(ADR 0004 の 1.13) |

### ウィンドウの枠・角・影

| 分け | 中身 |
| --- | --- |
| 仮の値 | 角の丸み 8(外枠の外側の線で測る)。枠は 1 px(比べる形:2 px)、前面 `#4C70A4`、背面 `#435470`。枠は外枠(タイトルバーとコンテンツ)の外側に描き、並べ方と大きさの計算は変えない。影は、前もって作って使い回す控えめなもの(下へ 2 ずらし、12 ほどでぼける。いちばん濃い所で不透明度 0.35)。最大化しているときは、角も影も枠も無し |
| 決まり | 角の外側(丸めて欠いた所)は、そのウィンドウのものとして扱わない(クリックは後ろへ、縁での大きさ変更の範囲に入る)。コンテンツの角は、角の丸みに合わせて切る(pixman のクリップ)。アプリが自分でタイトルバーを描く場合も、Seinas はいつもサーバーの側で飾りを描くと答える(xdg-decoration)ので、二重にはならない(アプリが答えを無視して自分で描く場合は、二重になる。今は見分けない) |

## 見本の画像に近いと言える条件(終わりの条件)

- 正解の画像(golden)を、fake screen の 1920x1080 で、見本の画像と同じ並び(同梱の壁紙、前面と背面のウィンドウ 2 枚、トーチとタスク 4 つのタスクバー、前面と背面の印、時計)にした画面で取る。時計は、テストのための口で時刻を決める。
- 上の「採った値」を、golden の画面のピクセルで測って表にする(高さ・大きさ・間隔・色)。
- 見本の画像(1080p に拡大したもの)と並べた画像と、タスクバー・タイトルバーを 4 倍にして並べた画像を作る。「近い」かどうかは、運用者が並べた画像を見て決める。数の表は、その材料にする。
