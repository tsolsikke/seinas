# ADR 0003: 利用者が選んだフォントで描けるようにする(置き場、一覧、役ごとの選び方、設定)

- 状態: 承認
- 日付: 2026-10-11

## 背景

利用者が、好きなフォント(TTF・OTF・TTC など)を使えるようにしたい(運用者の最低要件。2026-10-07)。Linux の fontconfig に当たる役目を、Seinas の中で、小さく持つ。

今の形(`docs/text-rendering.md`):

- `seinas-text` が、決まった名前の 2 つのファイル(BIZ UDPゴシック、GNU Unifont JP)を、1 つのディレクトリから読む。置き場は、引数 `--fonts DIR`、環境変数 `SEINAS_FONTS`、`target/fonts` の順で決まる。
- ファイルは、ヒープへ丸ごと読む(`std::fs::read`)。システムのフォントは探さない(cosmic-text の `fontconfig` の機能を外してある)。
- フォントの読み込み、名前での選択、無い文字のフォールバックの順(`UnifontFallback`)が、シェーピングと描画と同じ `TextPainter` の中に混ざっている。フォントの名前も定数で固定している(ADR 0001 の棚卸しで分かったこと)。
- 文字を描くプロセスは、コンポジタ(タイトルバー)とタスクバーの 2 つ。どちらも、同じフォントを別々に読んでいる。

測った値(2026-10-11、WSLg、release。fontdb 0.23 を直接使う小さなプログラムで):

| 量 | 値 |
| --- | --- |
| 置き場を調べて一覧を作る時間(`/usr/share/fonts` の 16 ファイルと、同梱の 3 ファイル。19 face) | 約 9 ms |
| 同梱の 3 本を、ヒープへ丸ごと読んだときのメモリー | VmRSS +14,332 kB |
| 同じ 3 本を、mmap でマップしたとき(描く前。触ったページだけが増える) | VmRSS +120 kB |

## 決定

### 1. 範囲

- Seinas が自分で描く文字だけを対象にする。今はコンポジタのタイトルバーとタスクバー、今後は `seinas-text` を使う Seinas のアプリ(端末など)。
- ほかのツールキットのアプリ(GTK など)が使うフォントの探し方は、対象にしない。fontconfig は使わない(ZeikOS に無く、持っていくものが大きい)。

### 2. フォントの置き場

次の置き場を、この順に探す。同じ名前のフォントが、いくつもの置き場にあるときは、後の置き場のものを使う(利用者が置いたものが勝つ)。

| 順 | 置き場 | Linux(開発) | ZeikOS |
| --- | --- | --- | --- |
| 1 | 同梱の既定のフォント | 今の決まり(`--fonts`、`SEINAS_FONTS`、`target/fonts`) | `/usr/share/seinas/fonts`(案) |
| 2 | システムの置き場 | `/usr/share/fonts` | `/usr/share/fonts` |
| 3 | 利用者の置き場 | `$XDG_DATA_HOME/fonts`(無ければ `~/.local/share/fonts`) | 同じ |
| 4 | 設定のファイルで足した置き場 | `dir = …` の行(下の 6) | 同じ |

- 置き場の下のディレクトリも探す(深さ 8 まで。シンボリックリンクはたどるが、同じディレクトリは 2 度見ない)。
- 対象にするファイルは、拡張子が `.ttf`・`.otf`・`.ttc`・`.otc` のもの(大文字と小文字は区別しない)。TTC・OTC は、中の face を全部、別のフォントとして一覧に入れる。
- WOFF・WOFF2、ビットマップのフォント(PCF、BDF)は、対象にしない。
- 1 ファイルが 64 MiB を越えるものは、一覧に入れず、ログに出す。大きな CJK の TTC(20〜30 MB)は入る大きさにする。
- テストと、置き場を決め打ちにしたいときのために、設定のファイルで、2 と 3 の置き場を使わないようにできる(`default-dirs = no`)。

### 3. 一覧の作り方

- 一覧に持つのは、ファイルのパス、face の番号(TTC の中の何番目か)、family の名前(フォントが持つ全部の言語の名前。英語と日本語のどちらでも選べるように)、太さ(100〜900)、斜体か、等幅か。Seinas の型で持つ。
- 一覧は、要るときだけ作る。設定のファイルが無いか、設定が同梱のフォントだけを指すときは、今と同じく同梱のファイルだけを読み、置き場は調べない(起動の時間と syscall が、今と変わらない)。同梱に無いフォントを指す設定があるときにだけ、置き場を全部調べる。(実装では変えた。下の「承認の後に変えたこと」の 1)
- 一覧のキャッシュ(ファイル)は、最初は持たない。上の測った値(19 face で約 9 ms)なら、起動のたびに調べてよい。ZeikOS の上で遅いと分かったら、`$XDG_CACHE_HOME/seinas/fonts.list`(パス・大きさ・更新時刻をキーにして、一覧の中身を書いたもの)を足す。

### 4. 役ごとに選ぶ

- 役は 3 つ:`ui`(タイトルバー、タスクバーなど)、`monospace`(端末、コード)、`fallback`(無い文字のフォールバック。順のある並び)。明朝などの役(`serif`)は、要るようになったら足せる形にしておく。
- 役ごとに、family の名前と太さ(既定 400)を指定する。名前は、大文字と小文字を区別せず、英語と日本語のどちらの名前でもよい。
- 指定に合うフォントの決め方は、CSS のフォントの選び方(名前が合うものの中から、太さと斜体がいちばん近いもの)にする。fontdb の `query` が、これを持っている。(実装では、fontdb の `query` を使わない。下の「承認の後に変えたこと」の 2)
- 既定:`ui` は BIZ UDPゴシック、`monospace` は BIZ UDゴシック、`fallback` は GNU Unifont JP。設定のファイルが無ければ、今と同じ形になる。
- 指定したフォントが見つからないときは、ログに出して、その役の既定を使う。既定も無ければ、今と同じ動き(フォールバックのフォントだけで描く、それも無ければ描かない)にする。

### 5. 無い文字のフォールバック

- `fallback` に書いた順に探す。その後に、いつも同梱の GNU Unifont JP を足す(利用者が消せない、最後のフォールバック)。どれにも無い文字は、今と同じく四角の枠で描く。
- 一覧の全部のフォントから、その文字を持つものを自動で探すこと(fontconfig の、文字の範囲を使った選び方)はしない。探すたびに多くのフォントを開くことになり、メモリーと時間が読めないため。要るようになったら、一覧に文字の範囲の要約を持たせて考える。
- 文字の種類(script)ごとにフォールバックを変えることも、最初はしない。

### 6. 設定のファイル

- 置き場:`$XDG_CONFIG_HOME/seinas/fonts.conf`(無ければ `~/.config/seinas/fonts.conf`)。引数 `--font-config PATH` で変えられる。
- 形式:1 行に `キー = 値` の小さな形式。`#` から行の終わりまでは、コメント。新しい依存(TOML などを読む crate)は足さない。

```text
# Seinas のフォントの設定
ui = Noto Sans JP
ui-weight = 400
monospace = BIZ UDGothic
fallback = Noto Sans CJK JP, Noto Color Emoji
dir = /home/user/fonts
```

| キー | 意味 |
| --- | --- |
| `ui`、`monospace` | 役のフォントの family の名前 |
| `ui-weight`、`monospace-weight` | 太さ(100〜900。既定 400) |
| `fallback` | 無い文字のフォールバックの family の名前を、コンマで区切って順に |
| `dir` | 足す置き場(何行でも) |
| `default-dirs` | `no` なら、システムと利用者の置き場を使わない |

- 読めない行、知らないキー、範囲の外の値は、ログに出して飛ばす。Seinas は止まらない。
- 読むのは、起動のとき。変えたら、そのプログラムを起動し直すと反映する(最初の形)。
- 動いている間に反映する仕組み(設定のプログラムから、コンポジタとシェルの部品へ「読み直して」を伝える)は、設定のプログラムを作るときに決める。inotify には頼らない(ZeikOS に無い見込み)。
- コンポジタとタスクバーは、それぞれが同じ設定のファイルを読む。

### 7. 読み込み方

- ファイルは、mmap(読むだけ)でマップして使う。fontdb の `memmap` の機能(cosmic-text の `std` で、すでに入っている)を使う。
  - 理由:文字を描くプロセスは、コンポジタ・タスクバー・アプリと増えていく。ヒープへ読むと、プロセスごとにフォントの大きさのぶん(同梱の 3 本で約 14 MB)増える。mmap なら、描くのに触ったページだけが増え、ページキャッシュはプロセスの間で共有される。
- mmap が失敗したときは、今と同じく、ヒープへ丸ごと読む。
- グリフのキャッシュに上限を入れる(案:1 プロセスあたり 4 MB。超えたら、古く使ったものから捨てる)。今は上限が無い(`docs/text-rendering.md`)。

### 8. ADR 0001 との整合

- `seinas-text` の中に `fonts` の module を作り、置き場の探索・一覧・設定の読み込み・役ごとの選択を、そこへ分ける。fontdb を使うのは、この module と、描く所(`TextPainter` の中)だけにする。
- 公開する型は、Seinas の型だけにする(一覧の 1 項目、役、設定、読めなかった理由)。呼ぶ側(コンポジタ、タスクバー)は、設定と置き場を `seinas-text` に渡すだけで、fontdb の型を見ない。
- 今の `FontFiles::in_dir` は、既定の設定(同梱のフォントだけ)を作る形で残す。

### 9. フォントのライセンス

- 利用者が置いたフォントは、それぞれのライセンスで、利用者が使うもの。Seinas はそれを配らないので、`THIRD-PARTY/` には入れない。
- 同梱の既定のフォントは、今どおり `THIRD-PARTY/fonts/` に記録する。同梱するフォントを増やすときも、同じ。
- 描いた結果(画面、golden)の扱いは、`docs/golden.md` の判断と同じ。
- 将来の設定のプログラムでは、フォントが持つ著作権とライセンスの欄(name テーブル)を見せる(案)。

## ZeikOS の上へ持っていくときの前提

- ファイルの mmap(`PROT_READ`、`MAP_PRIVATE`、fd を渡すもの)。無ければ、ヒープへ読む形で動くが、プロセスごとに 10〜14 MB 増える。
- 4 MiB を越えるファイルを読めること(ext2 の 2 段目の間接ブロック。同梱のフォントがすでに越えている)。
- 置き場を調べるときだけ:ディレクトリを読む `getdents64` と、`O_DIRECTORY` の `open`(musl の `opendir`)。既定の設定では使わない。
- 利用者の設定を書く(設定のプログラムが保存する)ときだけ:利用者が書けるファイルシステム。読むだけなら要らない。
- 環境変数 `HOME`・`XDG_CONFIG_HOME`・`XDG_DATA_HOME` が無ければ、利用者の置き場と設定のファイルは無いものとして扱う(止まらない)。
- 機能を入れたら、strace の差分を `docs/m3-syscalls.md` に記録する。

## 実装の刻み

| 順 | 内容 | 見込み |
| --- | --- | --- |
| 1 | `seinas-text` の中で、読み込みと選択を `fonts` の module に分ける(振る舞いは変えない。golden が変わらないことで確かめる) | 約 250 行 |
| 2 | 置き場の探索と一覧(下のディレクトリ、TTC の face、大きさの上限、`default-dirs`)と、そのテスト | 約 300 行 |
| 3 | 設定のファイルの読み方と、役ごとの選択(名前・太さ、見つからないとき、最後のフォールバック)と、そのテスト | 約 300 行 |
| 4 | mmap での読み込み(失敗したらヒープ)と、メモリーの計測(コンポジタとタスクバーを合わせた量) | 約 150 行 |
| 5 | コンポジタとタスクバーが設定のファイルを読む(`--font-config`)、文書、strace の記録 | 約 150 行 |
| 6 | グリフのキャッシュの上限 | 約 100 行 |

- 1〜6 で約 1,250 行。動いている間の反映と、設定のプログラムは、この後に別に決める。
- テストのフォントは、同梱のフォントを一時ディレクトリへコピーして使う(ホストの `/usr/share/fonts` に左右されないよう、テストでは `default-dirs = no` にする)。TTC は、テストのために小さな TTC を作るか、手元の TTC で確かめるかを、刻み 2 で決める。

## 承認の後に変えたこと

実装(2026-10-11)で、決定と違う形にしたもの。どちらも、実装の後に承認された。

1. 設定がフォントの名前を書いていれば、その名前が同梱のフォントの名前でも、置き場を調べる(決定 3 の「同梱のフォントだけを指すときは、置き場を調べない」を変えた)。
   - 理由:同梱のフォントと同じ名前のフォントを、利用者が置き場に置いたとき、後の置き場のものが勝つ(決定 2)ようにするため。名前だけを見て調べないと、利用者が置いたものが使われない。
   - 置き場を調べないのは、設定のファイルが無いときと、フォントの名前も置き場(`dir`)も書いていないときだけになる。このときの起動の時間・syscall・golden は、今と変わらない。
2. 太さの選び方は、fontdb の `query` を使わず、`fonts` の module が、一覧(Seinas の型)の上で、CSS の決まりに沿って自分で選ぶ(決定 4 の「fontdb の `query` が、これを持っている」を変えた)。
   - 理由:`query` は fontdb の `Database` に入れたフォントの中から選ぶので、置き場の順(後の置き場が勝つ)を入れられない。また、選ぶ所が fontdb の型に依ると、決定 8(公開するのは Seinas の型だけ)と、テストのしやすさに反する。
   - 選び方:名前が合うもの(大文字と小文字は区別しない)のうち、いちばん後の置き場のものだけを残し、斜体でないものを先にして、太さは CSS の決まり(400〜500 を指定したときは 500 まで太いほう、細いほう、500 より太いほうの順。それより細い指定は細いほうから、太い指定は太いほうから)で、いちばん近いものを選ぶ。

## 既知の危険

今は手当てをしていないもの。

### 動いている間に、マップしたフォントのファイルが切り詰められると、SIGBUS で止まる

- フォントのファイルは、fontdb(memmap2)が `PROT_READ`・`MAP_SHARED` でマップする(決定 7 を書いたときは `MAP_PRIVATE` の見込みだった)。マップしている間に、ファイルが切り詰められたり、短い内容で書き直されたりすると、ファイルの終わりより先のページに触ったときに SIGBUS が来て、プロセスが止まる。コンポジタなら、画面の全部が止まる。
- `MAP_PRIVATE` にしても防げない(切り詰められた先のページは、どちらでも読めない)。同じ大きさで内容を書き換えられたときは、止まらないが、壊れた内容を読む(グリフが乱れるか、読めないフォントとして扱われる)。
- 置き換えを `rename` で行う(パッケージの管理のプログラムの多くが、そうする)と、マップしている古いファイルは消えずに残るので、起きない。起きるのは、`cp` での上書きや、エディターでの直接の書き直しなど。
- 手当ての案(どれも、今は入れない):

| 案 | 欠点 |
| --- | --- |
| 小さなファイル(例えば 8 MiB まで)は、ヒープへ丸ごと読む | 同梱のフォントも入るので、プロセスごとにメモリーが増える(同梱の 3 本で約 14 MB)。mmap を選んだ理由がほぼ無くなり、大きなファイルの危険は残る。 |
| SIGBUS を受ける handler を入れ、フォントの範囲なら、その範囲を 0 のページ(`MAP_FIXED`・`MAP_ANONYMOUS`)で差し替えて続ける | signal の handler はプロセスの全体で 1 つなので、Smithay の shm の pool のための handler と、つなぎ合わせる必要がある。async-signal-safe の制約の中で、フォントの範囲を引く表を持つことになり、複雑で、テストもしにくい。 |
| 読み始める前に、ファイルを自分だけのもの(memfd など)へコピーしてからマップする | 起動のたびに、ファイルの全部を読んで書く時間がかかる。プロセスの間でページキャッシュを共有できなくなり、メモリーはヒープへ読むのと同じだけ増える。 |
| 描く前に、`fstat` で大きさが変わっていないかを確かめる | 確かめてから触るまでの間に切り詰められると防げない。描くたびに syscall が増える。 |
| 文書で「フォントは `rename` で置き換える」と案内する | 利用者の操作に頼るので、防げるとは限らない。手間は無い。 |

### ZeikOS は、今は 4 MiB を越えるファイルを読めない

- Seinas は、64 MiB を越えるファイルを一覧に入れない(決定 2)が、ZeikOS は、今は 4 MiB を越えるファイルを読めない(ext2 の 2 段目の間接ブロック)。4〜64 MiB のフォントは、一覧に入るのに、読めないことになる。同梱のフォント(BIZ UDPゴシック 4,669,688 バイト、BIZ UDゴシック 4,667,380 バイト、GNU Unifont JP 5,250,304 バイト)も、この範囲にある。
- ZeikOS の側で、4 MiB を越えるファイルを読めるようにする予定。それまでは、ZeikOS の上では、同梱のフォントで文字を描けない。
- 読めないとき、ZeikOS がエラーを返すのか、途中までの内容を返すのかは、確かめていない。途中までの内容を返すと、壊れたフォントとして扱われるか、上の SIGBUS と同じことが起きうる。ZeikOS の側の対応が入るまで、上限を Seinas の側で下げることはしない(下げると、同梱のフォントも使えなくなる)。

## 今は決めないもの

- 設定のプログラム(画面)と、動いている間の反映の仕組み。
- 文字の大きさの設定(今は 14 px に固定)と、太字・斜体の使い分け(タイトルを太字にする、など)。
- 絵文字(カラーのフォント)と、基本多言語面より上の文字のフォールバック。
- 可変フォント(variable font)の軸の指定。最初は、フォントの既定の位置だけを使う。
- 明朝などの役(`serif`)と、文字の種類ごとのフォールバック。

## 結果

- 利用者は、置き場にフォントを置き、設定のファイルに名前を書けば、そのフォントで Seinas の文字が描かれる。
- 設定が無ければ、今と同じ形で動く(起動の時間、syscall、golden が変わらない)。
- fontconfig を持たずに済み、ZeikOS へ持っていくものが増えない。代わりに、置き場の探索と選び方を、自分で持つ(保守の量が増える)。
- mmap を使うことで、文字を描くプロセスが増えても、メモリーが増えにくい。
