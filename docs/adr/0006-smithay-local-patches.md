# ADR 0006: Smithay の不具合は、fork の局所パッチで直す

## 状態

決定(2026-10-25)。fork のブランチ `seinas/0.7.0` を rev で参照する形にした(今の rev は `793c042e5583dcc75e2e92ce072087be38cb7419`。`docs/smithay-patches.md`)。

## 背景

- Seinas は Smithay 0.7.0 を使う。使っている所で、Smithay の不具合が見つかっている(IME の古い grab の破棄が新しい grab を外す、`wl_shm_pool.resize(0)` で panic する)。
- これまでは、Smithay の依存と `[patch.crates-io]` を変えない決まりで、Seinas の側の守りで避けてきた(ADR 0004 の 1.5 の、古い grab が残る間は新しい IME を断る守りなど)。守りで避けられない不具合(`resize(0)` はどのクライアントでもコンポジタを止められる)もある。
- 上流の Smithay では、関係する直しが進んでいない(input-method の PR #2147 は未マージ。2026-10-25)。

## 決定(運用者の決定、2026-10-21)

1. 基本は Smithay 0.7.0 を使う。バージョンは、決めて上げるときだけ上げる(`docs/smithay-patches.md` の「次のバージョンへ替えるときの手順」)。
2. 見つけた不具合は、Seinas の側で直す。上流との折衝はしない(上流へ出すかは、別に決める)。
3. 直しは、GitHub の fork(`tsolsikke/smithay`)のブランチ `seinas/<バージョン>` に、1 つずつのコミットで積む。直しと、その回帰のテストは、別のコミットにする。
4. Seinas は、`Cargo.toml` の `[patch.crates-io]` で、fork のブランチを git と rev を固定した形で参照する。path の形ではコミットしない。
5. fork への push は運用者が行う。ブランチは force push しない(rev を固定して参照するため)。直しは、ブランチの上に積む。
6. パッチの一覧(中身と理由、上流の状態、回帰のテスト、次のバージョンで外せるか)は `docs/smithay-patches.md` に置き、パッチを足す・外すときに一緒に直す。
7. fork に積むのは、Seinas が当たる不具合だけにする(fork を小さく保つ)。

## 理由

- Seinas の側の守りは、不具合の形に合わせた回り道で、守りの側にも限りが残る(1.5 の守りは、古い grab が残る間、新しい IME を使えなくする)。直すべき所で直すほうが、Seinas の作りが素直になる。
- rev を固定するので、ビルドは再現できる(`Cargo.lock` に hash が残る)。crates.io の 0.7.0 と同じソースからのブランチなので、差はパッチだけになる。

## 結果

- Smithay の依存を変える決まり(CLAUDE.md)は、このパッチの作業の中でだけ変えてよい、と改める。
- バージョンを上げるときに、パッチを 1 つずつ確かめる手間が増える。
