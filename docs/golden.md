# 正解データ(golden)のテスト

ADR 0001(`docs/adr/0001-replaceable-boundaries.md`)の決定 4 の実装です。
置き換える前の出力を、正解データとしてリポジトリに保存し、今の出力と機械で比べます。
外部ライブラリを置き換えるときや、GPU で描画する構成を足すときに、出力が変わっていないことを確かめるためのものです。

## 対象

| 対象 | crate | ケース | 形式 |
| --- | --- | --- | --- |
| A. 描画の合成 | `seinas-render` | 単色の四角の重なりと画面の 4 辺での切り取り、メモリーのイメージ(不透明)、メモリーのイメージ(半透明、premultiplied alpha)、要素なし。4 ケース | PPM |
| B. テキスト描画 | `seinas-text` | 4 つの文字列(ASCII、かな、漢字、フォールバックと欠けた字)× 3 つの大きさ(13 px はヒンティングなし、14 px と 16 px はあり)。12 ケースと、戻り値(`Drawn`)の一覧 `cases.txt` | PGM(カバレッジ) |
| C. タイトルバー | `seinas-frontend` | activated とそうでないもの × close ボタンの hover の有無、長いタイトルの切り詰め、フォントなし、close ボタンより狭い幅。7 ケース | PPM |
| D. fbdev の blit | `seinas-fbdev` | XRGB、ARGB、XBGR、RGBX、オフセットと行の余白つき。5 ケース | raw(バッファのバイト列) |

正解データは、各 crate の `tests/golden/` にあります(説明は `crates/seinas-text/tests/golden/README.md`)。テストは `tests/golden.rs`(`harness = false`)で、ふだんの `cargo test` で動きます。
入力はテストのコードに書いてあり、保存するのは出力だけです。
比べる部品は `crates/seinas-golden` にあります(テストだけで使う crate で、バイナリには入りません)。

## 比べ方

- 今は、すべての対象を完全一致で比べます。同じ実装に同じ入力を渡すと同じバイトが出ることを、ホスト(glibc)と musl、pixman の SIMD の経路の有無で確かめてあります。
- 比べる部品は、許す差(ちがってよいピクセルの数、1 チャンネルの差の上限)を持てる形ですが、今はどれも 0 です。
- 許す差を 0 より大きくしてよいのは、テキスト描画(B)とタイトルバー(C)だけです。描画の合成(A)と fbdev の blit(D)は、いつも完全一致です。
- B・C に差を許すのは、置き換えのときに限ります。そのコミットの中でテストに値を書き、理由をコミットメッセージに書きます。目安:ちがうピクセルがインクのピクセルの 1% 以下、インクを囲む矩形のずれが 1 px 以下、`Drawn` の値(幅、切り詰め、フォールバックと欠けた字の数)は一致。
- ちがったときは、テストが失敗し、ちがうピクセルの数、いちばん大きいチャンネルの差、ちがう所を囲む矩形を出します。あわせて、今の出力と差分の画像(ちがう所が赤)を `target/golden-actual/<crate>/` に書き出します。

## フォント

B と C の多くのケースは、`tools/fetch-fonts.sh` が置いたフォント(`target/fonts`)を使います。

- テストは、フォントのファイル(`.ttf` と `.otf`)の SHA-256 を、`tools/fetch-fonts.sh` に書かれた値と比べます。ちがえば、いつも失敗にします(別のバージョンのフォントで比べないため)。
- フォントが無いときも、失敗にします(黙ってスキップしません)。
- 手元でだけ、環境変数 `SEINAS_SKIP_FONT_GOLDEN=1` を付けると、フォントの要るケースをスキップできます。スキップしたケースの数は、テストの出力に出ます。CI(環境変数 `CI` がある)と、正解データの作り直しでは、この指定は効きません。

## 作り直し

```bash
tools/update-golden.sh
```

4 つの crate の golden テストを、環境変数 `SEINAS_UPDATE_GOLDEN=1` を付けてホストで動かします。テストは、比べるかわりに正解データを上書きし、古いファイルとの差を 1 ケース 1 行で出します。最後に `git diff --stat` を出します。

作り直すときの決まり:

- コミットメッセージの本文に、作り直した理由と、差分の要約(変わったファイルの数、ケースごとのちがうピクセルの数といちばん大きい差)を書きます。
- 正解データの作り直しと、コードの変更は、同じコミットに混ぜません。例外は、下の「バージョン上げ」で(b)に当たる場合だけです。
- 置き換え(部品を自前のコードなどに替える)のコミットでは、正解データを作り直しません。置き換えた後も、置き換える前の正解データでテストを通します。
- テストが失敗したときに自動で上書きすることは、しません。

## バージョン上げ

外部ライブラリのバージョンを上げたときと、フォントのファイルを更新したとき(`tools/fetch-fonts.sh` のバージョンや SHA-256 を変えたとき)は、出力の変わり方で、次のように判断します。

- (a) 変わらない:そのまま。
- (b) 小さな変化:変わったのがアンチエイリアスの端のピクセルだけで、インクを囲む矩形と、`Drawn` の値(幅、切り詰め、フォールバックと欠けた字の数)が変わらない。
  バージョンを上げるコミット(またはフォントを更新するコミット)の中で、`tools/update-golden.sh` で作り直してよいです。本文に差分の要約を書きます。
  例:cosmic-text を上げて、グリフの端が 1 ピクセル変わった場合。
- (c) 大きな変化:グリフの形や位置が変わる(矩形が 1 px より大きく動く)、`Drawn` の値が変わる、フォールバックの起き方が変わる、描画の合成(A)や fbdev の blit(D)が少しでも変わる。
  振る舞いの変化として報告し、作り直す前に判断を仰ぎます。必要なら、バージョンを今のままに止めます。

CI はいつも golden テストを動かすので、バージョン上げで出力が変われば、その場で失敗して気づけます。

## ホストと musl

- 正解データは、ホストで作ります(`tools/update-golden.sh`)。
- CI は、ホストのジョブと musl のジョブの両方で、同じ正解データと比べます。
- もしホストと musl で出力がちがったら、それは不具合として報告し、配っているもの(musl の静的 PIE)に合わせます。ターゲットごとに正解データを持つことはしません。

## ライセンス

テキストを描いた正解データ(B と C)は、BIZ UDPゴシックと GNU Unifont JP(どちらも SIL Open Font License 1.1 で使用)で描いたものです。

- OFL 1.1 の条件 5 は、フォントを使って作ったもの(document)には当てはまりません。OFL の FAQ(1.1、1.1.1)も、フォントを使って作ったグラフィックスは作った人のもので、条件が付くのはフォントそのものを再配布・変更するときだけ、としています。
- 描いた結果のピクセルは、Font Software でも Modified Version でもないと判断しています(法律の専門家には確かめていません)。
- ビットマップフォントに近いもの(グリフを全部並べた画像)にならないよう、保存するのは短い文字列だけにします。
