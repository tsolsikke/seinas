# ウィンドウの重ね方と置き方

クライアントのウィンドウ(toplevel)を、どの順に重ね、どこに置くかの決まりです。
フロントエンド(`crates/seinas-frontend` の `src/stack.rs`)で決めているので、入れ子の構成(`seinas`)でも、フロントエンドとfbdevの構成(`seinas-standalone`)でも、同じに振る舞います。

## タイトルバーと、ウィンドウの外枠

装飾(xdg-decoration)を取り決めて server_side になったウィンドウに、Seinas が、上にタイトルバーを付けます(下の「飾りを描く側の取り決め」)。取り決めていないウィンドウには、タイトルバーも枠も角も影も付けません(外枠は、コンテンツと同じ矩形です)。

- タイトルバーの高さは36ピクセルで、幅は、クライアントが描くコンテンツと同じです。コンテンツは、タイトルバーのすぐ下に置きます。
- タイトルバーとコンテンツを合わせたものを、ウィンドウの「外枠」と呼びます。コンテンツが320x240なら、外枠は320x276です。
- スロットや、押した所のヒット判定は、外枠で決めます(角は、下の「枠・角・影」のとおり丸く欠きます)。
- まだ絵を出していないウィンドウ(大きさが無い)には、タイトルバーも付けません。
- 大きさと色の値は、テーマのトークン(`crates/seinas-theme` の `title_bar` と `frame`)にあります。見た目の仕様は `docs/ui-spec.md` にあります。

タイトルバーに出すもの:

- 左の端から10ピクセル空けて、アプリのアイコン(20x20。縦は中央)を出します。アイコンは、app_id から、データの置き場の `.desktop` とアイコンのテーマを探して読みます(`docs/adr/0007-png-for-app-icons.md`)。見つからなければ、既定のアイコンです。
- クライアントが付けたタイトル(xdg_toplevelの `set_title`)を、アイコンの右に8ピクセル空けて、左に寄せて出します。右のボタンの手前にも、10ピクセル空けます。
- タイトルが無い(または空白だけの)ときは、app_id(`set_app_id`)を出します。それも無ければ、タイトルバーだけを出します。
- タイトルバーの右の端には、ボタンがあります。右から、閉じる(下の「閉じる」)、最大化(または元に戻す)、最小化です(下の「最大化・最小化」)。タイトルは、その手前に収めます。
- 収まらないタイトルは、末尾を切って「…」を付けます。
- タイトルやapp_idが変わると、タイトルバーを再描画します。
- 文字の大きさは15ピクセルで、フォントはBIZ UDPゴシックです。このフォントに無い文字は、控えのGNU Unifont JPで描きます。どちらにも無い文字は、四角の枠で描きます(`docs/text-rendering.md`)。
- フォントのファイルが読めないときは、タイトルバーだけを描き、原因をログに出します。Seinasは止まりません。

タイトルバーの色:

| ウィンドウ | タイトルバーの色 | タイトルの色 |
| --- | --- | --- |
| activated(いちばん手前) | 濃い紺(`#1a273d`) | 白に近い灰色(`#f8f8f8`) |
| activated でない | もっと濃い紺(`#152034`) | 青みの灰色(`#909cb0`) |

枠・角・影:

- 枠:外枠の外側に、太さ1ピクセルの線を描きます(activated は `#4c70a4`、そうでないものは `#435470`)。枠は外枠の外に置くので、並べ方と大きさの計算は変わりません。
- 角:外側の線で丸み8ピクセルの角にします。外枠(タイトルバーの上の2つの角と、コンテンツの下の2つの角)は、丸み7ピクセル(8から枠の太さを引いたもの)で欠きます。タイトルバーの角は縁をなめらかにし、コンテンツの角は、ピクセルの中心が丸みの外の所を描きません。
- 影:外枠のまわりに、下へ2ピクセルずらした、薄い影(いちばん濃い所の不透明度0.35、縁から12ピクセルで消える)を描きます。影の絵は、ウィンドウの大きさが変わったときだけ作り直します。
- ヒット:外枠の角を欠いた所は、そのウィンドウのものとしません。押すと、後ろのウィンドウ(か、デスクトップ)にヒットします。ただし、そこはサイズ変更の境界の角です(下の「縁と角でのサイズ変更」)。
- 最大化しているウィンドウには、枠・角・影を付けません(角も欠きません)。

飾りを描く側の取り決め(xdg-decoration):

決まりの根拠は xdg-decoration の仕様です。取り決めないクライアントは、自分の判断で飾りを描きます。コンポジタは、クライアントの希望と違うモードを選んでもかまいません。

- 判定は、ウィンドウ(xdg_toplevel)ごとです。接続や app_id の単位にはしません。Seinas は `zxdg_decoration_manager_v1` を公開していますが、manager を bind しただけでは、取り決めたことにしません。
- 装飾のオブジェクト(`zxdg_toplevel_decoration_v1`)が無いウィンドウ:タイトルバー・枠・角・影を付けません。クライアントが自分で描きます(GTK などは、このプロトコルを使わずに自分で描くので、タイトルバーは 1 つです)。
- 装飾のオブジェクトを作ったウィンドウ:いつも「サーバーの側(Seinas)で描く」(server_side)と答え、Seinas が描きます。作ったとき、モードを求められたとき(client_side を求められても)、求めを取り消されたとき(unset_mode)のどれも同じです。client_side を求められても server_side で答えるのは、仕様がコンポジタに違うモードを選ぶことを認めており、クライアントは configure で伝えたモードに従うので、タイトルバーが二重にならないためです。そのため、client_side のモードが効くことはありません(効いていれば、描きません)。
- モードの切り替えは、configure・ack_configure・commit と合わせます。答えは次の configure で伝え、Seinas が描き始めるのは、クライアントがその configure に応じた後の commit からです(いまの状態の装飾のモードで決めます)。求めを受けた時点では、タイトルバーの高さを変えません。
- 最初の configure は、クライアントの最初の commit のときに送ります(xdg-shell の決まり)。大きさは 0x0(クライアントに任せる)です(下の「大きさ」)。最大化・全画面を最初の commit の前に頼まれていれば、取り決めに合わせたコンテンツの大きさ(タイトルバーのぶんを引くか)を伝えます。最大化しているウィンドウが後から取り決めたときは、タイトルバーのぶんを引いた大きさを伝え直します。
- クライアントが決めたウィンドウの幾何(`xdg_surface.set_window_geometry`)があれば、その矩形をコンテンツとして扱い、外枠の大きさと位置・ポインターのヒット・置き方は、その矩形で決めます。幾何の外(クライアントが自分で描く影など)は、描きますが、ウィンドウの大きさには数えません。ポインターの位置は、クライアントへは画面(surface)の左上からの位置で渡します。
- 自分で飾りを描くクライアントの移動とサイズ変更の頼み(`xdg_toplevel.move`・`resize`)は、飾りを Seinas が描くウィンドウと同じ条件で受けます(そのクライアントのコンテンツの上でボタンが押されている間だけ。下の「クライアントから頼まれる移動」と「クライアントから頼まれるサイズ変更」)。
- 飾りを何も描かないクライアントのために、ウィンドウを動かす修飾キー(既定は Alt。`seinas.conf` の `window-drag`)を押しながら、ウィンドウのどこでもドラッグすると、左のボタンで動かし、右のボタンで大きさを変えます(下の「修飾キーとドラッグ」)。
- 知られている制限:クライアントが装飾のオブジェクトを消したこと(`destroy`)は、Smithay の中だけで扱われ、Seinas には分かりません。消した後も、Seinas は飾りを描き続けます(仕様では、次の commit から描かないことになっています)。直すには、Smithay の局所パッチが要ります(今は直さない。運用者の決定。2026-10-26)。

## layer surface と使える範囲

タスクバー・メニュー・デスクトップは、コンポジタの外の別のプログラム(シェルの部品)として作ります(`docs/adr/0002-shell-components.md`)。
シェルの部品は、wlr-layer-shell(`zwlr_layer_shell_v1`、バージョン 4)で、layer surface を出します。

- layer-shell の global は、シェルの部品のためのソケット(ふだんのソケットのパスの名前に `-shell` を入れたもの(名前に拡張子があれば、その前に入れる。`docs/standalone.md`)。入れ子の構成では `seinas-0-shell`)からつないだクライアントにだけ見えます。ふだんのソケットのクライアントには、global そのものが見えません。
- 層は、奥から background、bottom、(通常のウィンドウ)、top、overlay の順に重なります。同じ層の中では、後から出た layer surface が手前です。
- 位置と大きさ(anchor、margin、exclusive zone、頼んだ大きさ)の計算は、Smithay の `LayerMap` に任せています。layer surface の commit のたびに並べ直し、最初の commit で最初の configure を送ります。
- 画面は 1 つなので、layer surface が output を指定しても、見ません。

使える範囲(usable area):

- 使える範囲は、画面から、layer surface の exclusive zone を除いた矩形です。exclusive zone を持つ layer surface が無ければ、画面の全体です。
- 新しいウィンドウのスロット、configure で伝える大きさ、ドラッグで外へ出せる範囲は、使える範囲を基準にします(下の「置き方」「大きさ」「動かす」)。最大化を入れるときも、使える範囲を基準にします。
- 使える範囲が変わったとき(exclusive zone を持つ layer surface が出た・去った・変わった)は、スロットにあるウィンドウを新しい範囲の同じスロットへ移し、動かされたウィンドウは、タイトルバーが新しい範囲に入るように動かします。すでに configure で伝えた大きさは、送り直しません。

ポインター:

- ボタンを押していない間は、top と overlay の layer surface が、ウィンドウより先にポインターのイベントを受け取ります。その上でボタンを押しても、下のウィンドウは raise されず、ドラッグや close ボタンも働きません。
- ウィンドウの上でない所では、bottom と background の layer surface が、ポインターのイベントを受け取ります。
- layer surface のポップアップ(`zwlr_layer_surface_v1.get_popup`。タスクバーのメニューなど)は、その layer surface のすぐ手前に描きます(下の「ポップアップ」)。

キーボード(`keyboard_interactivity`。wlr-layer-shell のバージョン 4 の決まりのとおり):

- none:キーボードのフォーカスを渡しません。押しても渡しません。
- exclusive:top と overlay の層では、出ている間、キーボードのフォーカスを独り占めします(ウィンドウを押しても、移りません)。手前の層のもの、同じ層では後から出たものが先です。消えたら、元のフォーカスに戻ります。bottom と background の層では、決まりの「exclusive は top と overlay の層でだけ働き、ほかの層では on_demand と同じに扱ってよい」に従い、on_demand と同じに扱います。
- on_demand:押したときに、キーボードのフォーカスを渡します。ほかの所(ウィンドウ、ほかの layer surface、何も無い所)を押したら外し、activated のウィンドウへ戻します。

## ウィンドウの一覧と操作(foreign-toplevel)

タスクバーなどのシェルの部品に、ウィンドウの一覧と、ウィンドウを操作するプロトコルを見せます(`docs/adr/0002-shell-components.md`)。

- 公開するのは、wlr-foreign-toplevel-management(`zwlr_foreign_toplevel_manager_v1`、バージョン 3)と、ext-foreign-toplevel-list(`ext_foreign_toplevel_list_v1`、バージョン 1。読むだけの一覧)の 2 つです。どちらの global も、layer-shell と同じく、シェルの部品のためのソケットからつないだクライアントにだけ見えます。
- 一覧に載るのは、絵を出した(map した)ウィンドウだけです。一覧の順は map した順で、スタックの順とは別です。絵を外したウィンドウは、一覧から外れます(closed)。
- 送る内容は、タイトル・app_id(付けていなければ送らない)、output(output_enter。output は 1 つで、wl_output を後から bind したクライアントには、そのときに送る)、状態です。状態は、activated(最小化していないうちの、いちばん手前のウィンドウ)、maximized、minimized です(全画面は、まだ持っていません)。タイトル・app_id・状態が変わるたびに、変わったものと done を送ります。ウィンドウが去ったら closed を送ります。
- 頼みの扱い:
  - activate:そのウィンドウを raise して、activated にします(クリックで raise したときと同じ)。seat の指定は見ません。
  - close:クライアントに、閉じるように頼みます(閉じるボタンと同じ)。応じるかどうかは、クライアントしだいです。
  - activate は、最小化しているウィンドウなら、戻してから raise します。
  - set_maximized・unset_maximized:最大化と、元に戻す(タイトルバーの最大化のボタンと同じ。下の「最大化・最小化」)。
  - set_minimized・unset_minimized:最小化と、戻す。戻すと、raise して activated にします。
  - set_fullscreen・unset_fullscreen:受けますが、今は何もしません(状態も変えません。ログに 1 行出します)。
  - set_rectangle:受け取って覚えるだけです(最小化のアニメーションの行き先に使えますが、今は使いません)。幅か高さが負なら、プロトコルのエラー(invalid_rectangle)で切ります。
  - stop:finished を送り、それからは新しいウィンドウを送りません。前から持っている handle には、変化を送り続けます。
- 閉じたウィンドウの handle への頼みは、何もしません。

## 重ね方

- 新しくできたウィンドウは、いちばん手前に来ます。
- ウィンドウが去ると、その下にあったものが見えるようになります。残ったウィンドウどうしの順は変わりません。

## クリックで raise する

ポインターのボタンを押すと、押した所にある、いちばん手前のウィンドウが、raise されます。

- 出るのは、押した所で見えているウィンドウです。奥のウィンドウは、見えている端(手前のウィンドウに隠れていない所)を押すと出せます。タイトルバーを押しても、同じです。
- ほかのウィンドウどうしの順は、変わりません。
- スロット(位置と、スロット番号)は、変わりません。重なる順だけが変わります。
- すでにいちばん手前のウィンドウを押したときは、何も変わりません。
- どのウィンドウの上でもない所を押したときは、何も変わりません。
- どのボタンでも同じです。
- コンテンツを押したイベント(button)は、raise したウィンドウへ、いつもどおり渡します。raise するだけで、イベントを消しません。タイトルバーを押したイベントは、クライアントには渡しません。
- まだ絵を出していないウィンドウ(大きさが無い)には、ヒットしません。

フロントエンドと fbdev の構成(`seinas-standalone`)は、入力の装置を扱わないので、ふだんの起動では、ポインターでの操作(raise、動かす、閉じる、サイズ変更)が働きません。決まりそのものは、同じものを持っています。

## 動かす

タイトルバーを、左のボタンで grab して動かすと、ウィンドウが付いてきます。

- grab できるのは、タイトルバーのうち、閉じるボタンを除いた所です。押した時点で、そのウィンドウは raise されます。
- 押してから4ピクセル動くまでは、動かしません。raise するだけのつもりで押したときに、ずれないようにするためです。
  4ピクセルを超えると動き始め、その後は、押した点からのずれのぶんだけ、ちょうど動きます(しきい値のぶんも含みます)。
- ボタンを離すと、終わります。
- 動かしている間、ポインターのイベントは、どのクライアントにも渡しません。
- 左でないボタンでタイトルバーを押したときは、raise するだけです。
- 動かしている間に、そのウィンドウが去ったときは、何も動かさずに終わります。

画面の外へ出せる範囲には、限りがあります。タイトルバーを、もう一度 grab できるようにするためです。
限りは、使える範囲(画面から、タスクバーなどの exclusive zone を除いた矩形)を基準にします。タスクバーの下に、タイトルバーが隠れないようにするためです。

| 向き | 限り |
| --- | --- |
| 上 | タイトルバーの上の端は、使える範囲の上の端より上へ行かない |
| 下 | タイトルバーの全体が、使える範囲の中に残る(コンテンツは、その下へ出てよい) |
| 右 | タイトルバーの左の 48 ピクセルが、使える範囲の中に残る |
| 左 | タイトルバーの右の 180 ピクセル(48 と、ボタンがいちばん多いときの 3 つ分の 132)が、使える範囲の中に残る。ボタンの手前に、grab できる所が残るようにするため |

左右とも、タイトルバーがそれより短ければ、その全体が残ります。
800x600 の画面で、外枠が 320x276 のウィンドウなら、外枠の左上は、横が -140〜752、縦が 0〜564 の範囲に収まります。
限りに当たっても、ポインターが戻れば、また付いてきます。

クライアントから頼まれる移動(xdg_toplevelの `move`)も、受けます。

- 受けるのは、そのクライアントのコンテンツの上でボタンが押されている間の頼みだけです(頼みに付いてくる通し番号が、いま押されているボタンのものであることを確かめます)。それ以外の頼みは、何もせずに捨てます。
- 受けると、そのボタンを離すまで、タイトルバーを grab したときと同じに動かします。しきい値は置かず、ボタンを押した点からのずれのぶんだけ動かします。画面の外の限りも、同じです。
- 受けた後、ボタンを離すまでのポインターのイベントは、クライアントには渡しません。

## サイズ変更

ウィンドウの縁と角をドラッグすると、大きさが変わります(Windows 11 と同じく、見えない境界を外枠の外側に置きます)。

- サイズ変更の境界は、外枠(タイトルバーを含めた矩形)の外側の 8 ピクセルです。上下左右の 4 辺と、4 つの角があります。外枠の角を丸く欠いた所(上の「枠・角・影」)も、その角の境界です。
- 角は、境界の角の部分に加えて、左右の境界の上下の端から 16 ピクセル(上下の境界も、左右の端から 16 ピクセル)までです。角に当てやすくするためです。
- 境界の上では、カーソルが、その辺の向きのサイズ変更の形になります(入れ子の構成。fbdev の構成には、まだカーソルの絵がありません)。境界の上にある間は、ポインターのイベントを、その下のウィンドウには渡しません。
- 境界は、手前のウィンドウのものが先にヒットします。手前のウィンドウの境界に重なった所では、奥のウィンドウの閉じるボタンにもヒットしません。
- 左のボタンで境界を押すと、そのウィンドウは raise され、サイズ変更が始まります。左でないボタンでは、raise するだけです。
- ドラッグの間は、押した点からのずれのぶんだけ、動かす辺を動かした大きさを、configure で伝えます(resizing の状態つき)。大きさが変わったときだけ送ります。ボタンを離すと、最後の大きさを、resizing の状態を外して、もう一度伝えます。
- 大きさは、コンテンツの最小(クライアントの `set_min_size` と、Seinas の最小 96x48 の大きいほう)と、クライアントの最大(`set_max_size`。0 なら限らない)を守ります。動かさない向きの大きさは、そのままです。
- 上の辺を動かすときは、タイトルバーの上の端が、使える範囲の上の端より上へ行かないようにします。
- 左か上の辺を動かすときは、反対の辺(右か下)の位置を保ちます。クライアントが新しい大きさの絵を出したときに、その大きさに合わせて、外枠の左上を動かします。クライアントが大きさに従わなければ、位置も変わりません。
- 外枠の左上が変わったウィンドウは、動かしたウィンドウと同じく、スロット番号を手放します。右か下の辺だけを動かしたときは、スロット番号を持ったままです。
- 最大化しているウィンドウは、サイズ変更できません(境界がありません)。全画面は、まだありません。

クライアントから頼まれるサイズ変更(xdg_toplevel の `resize`)も、受けます。

- 受ける条件は、クライアントから頼まれる移動と同じです(そのクライアントのコンテンツの上でボタンが押されている間だけ)。加えて、辺の指定が無いものと、サイズ変更できないウィンドウからの頼みは、受けません。
- 受けると、そのボタンを離すまで、頼まれた辺の境界を grab したときと同じに扱います。押した点からのずれのぶんだけ変えます(頼みが届くまでに動いたぶんも含みます)。

## 修飾キーとドラッグ

ウィンドウを動かす修飾キー(既定は Alt)を押しながら、ウィンドウのどこ(コンテンツ、タイトルバー、ボタン)でもドラッグすると、Seinas がウィンドウを動かすか、大きさを変えます。飾りを何も描かないクライアント(装飾を取り決めず、自分でもタイトルバーを描かないもの)でも、動かせるようにするためです。

- 左のボタン:タイトルバーを grab したときと同じに動かします(4 ピクセルのしきい値、画面の外の限り、上端での最大化の予告、最大化しているウィンドウを戻すことも同じ)。ダブルクリックにはしません。
- 右のボタン:外枠を縦と横に 3 つずつに分け、押した点に近い辺を動かして大きさを変えます(左の 3 分の 1 なら左の辺、右の 3 分の 1 なら右の辺。縦も同じ。真ん中なら右下の角)。最大化しているウィンドウと、大きさの決まったウィンドウでは、raise するだけです。
- 押した時点で raise します。押したこと・離したことは、クライアントへ渡しません。修飾キーそのもの(Alt を押したこと)は、いつもどおりフォーカスのあるクライアントへ渡します。
- 押している修飾キーが、設定とちょうど同じときに働きます(Alt なら、Ctrl や Shift も一緒に押しているときは働きません)。サイズ変更の境界の上では、修飾キーが無いときと同じです。
- 既定を Alt にした理由:入れ子の構成(WSLg)で、Alt は Seinas に届きます(Alt+Shift+F12 で確かめた。2026-10-15)。Super(Windows キー)は、Windows が先に使います。Alt を押しながらのドラッグが WSLg で届くかは、物理的なキーでまだ確かめていません。変えるときは、`seinas.conf` の `window-drag`(`docs/config.md`)。

## 閉じる

タイトルバーの右の端に、閉じるボタンがあります。

- 大きさは44x36ピクセル(幅44、高さはタイトルバーと同じ)で、タイトルバーの右の端と上の端に、ぴったり付いています。ヒットの範囲も、この矩形の全体です。
- 見た目は「×」の印です。フォントが無くても出るように、文字ではなく、縁をなめらかにした線で描いています(16x16ピクセル、太さ約1.4ピクセル)。色は、タイトルと同じです。
- 閉じるボタンの地が赤くなるのは、ポインターを乗せたとき(と、下の「応答なし」のとき)だけです。
- ポインターを乗せると、ボタンの地が赤(`#c42b1c`)に、印が白(`#ffffff`)になります。
- 左のボタンで押して、そのボタンの上で離すと、クライアントに、閉じるように頼みます(xdg_toplevelの `close`)。
- 押したまま外へ出すと、地の色が元に戻ります。そのまま外で離すと、取り消しです。離す前に戻せば、また赤になり、閉じられます。
- 押した時点で、そのウィンドウは raise されます。奥のウィンドウの閉じるボタンも、見えていれば、1回の操作で効きます。
  手前のウィンドウに隠れているボタンには、ヒットしません。
- 閉じるボタンを押している間は、ウィンドウは動きません。
- 頼むだけなので、応じるかどうかは、クライアントしだいです。応じないクライアントのウィンドウは、そのまま残ります。もう一度押せば、もう一度頼みます。
  ただし、応答なしのクライアント(下の「応答なし」)は、もう一度押すと、接続を切ります。

### 応答なし

閉じるのに応じないクライアントのうち、ping に答えないものを「応答なし」とし、閉じるボタンで接続を切れるようにします。

- 閉じるように頼む(閉じるボタンと、foreign-toplevel の close)ときに、そのクライアントへ xdg_wm_base の ping も送ります。すでに pong を待っていれば、送り直しません。ping を送るのは、このときだけです(いつも見張ることは、していません)。
- 決まった時間の中に pong が返らなければ、そのクライアントのウィンドウに、応答なしの印を付けます。
  - 時間の既定は 5 秒です。Windows が、メッセージを処理しないウィンドウを「応答なし」とするまでの時間(5 秒)に倣いました。ふつうのクライアントは、ping にすぐ答えるので、5 秒は、重い処理の途中のクライアントを誤って印を付けない程度に長く、利用者が待ちくたびれない程度に短い時間です。
  - テストのために、起動オプション `--ping-timeout MS` で変えられます(seinas-standalone と、入れ子の構成の `seinas` の両方)。
- 印を付けたら、次の入力を待たずに、すぐ再描画します。入れ子の構成では、親が前の絵を使っている間は、親の frame コールバックで描きます(何もしていない間に、決まった間隔で起きることはしない)。
- close に応じずに残っていても、pong を返すクライアント(保存するかを尋ねているアプリなど)は正常として扱い、印を付けません。
- 印を付けた後でも、pong が返ってきたら、印を外します。
- 印:タイトルバーのタイトルの後に「(応答なし)」を付け、閉じるボタンの地を暗い赤(`#8a1f14`。印は白)にします。ポインターを乗せると、ふつうの赤(`#c42b1c`)になります。タイトルが長いときは、「(応答なし)」を切らずに出し、タイトルのほうを切ります。
- 印の付いたウィンドウの閉じるボタンを押すと、そのクライアントの Wayland の接続を切ります(xdg_wm_base の `unresponsive` のエラーを送る)。確認のダイアログは出しません。
  - 切ったクライアントのウィンドウは、全部消えます。foreign-toplevel の一覧からも消え(closed)、キーボードのフォーカスと activated は、次のウィンドウへ移ります。Seinas と、ほかのクライアントは、動き続けます。
  - 切ったことは、ログに出します(`disconnecting a client that does not respond (the window "…"); its process is not killed`)。印を付けたときと、外したときも、ログに出します。
  - 印の無いウィンドウでは、今までどおり、閉じるように頼むだけです。強制的には切りません。
- タスクバーに送るタイトル(foreign-toplevel の title)には、「(応答なし)」を付けません。title は、クライアントが付けた名前として送る決まりのもので、Seinas の判断を混ぜると、タイトルでウィンドウを見分けるシェルの部品が迷い、印を付け外しするたびに、タイトルが変わったことを送ることにもなるためです。タスクバーに応答なしを出すときは、一覧に状態を足す形で、別に考えます。
- プロセスは kill しません。切るのは、Wayland の接続だけです。
  - 固まったプロセスは、接続を切っても、裏で動き続ける(残る)ことがあります。そのときは、利用者が端末などから止めます。
  - kill しない理由:Wayland の接続から分かる pid(SO_PEERCRED)は、接続した時点のものです。そのプロセスが終わって、同じ pid が別のプロセスに使い回されていると、関係の無いプロセスを止めてしまいます。また、コンテナや pid の名前空間の中のクライアントでは、Seinas から見える pid と、クライアントの中の pid がずれます。ZeikOS の上で同じことをするには、kill(とシグナル)の仕組みが要ります。

## 最大化・最小化

タイトルバーの右の端に、閉じるボタンの左から、最大化(または元に戻す)と最小化のボタンを並べます。どちらも 44x36 ピクセルで、印は太さ 1 ピクセルの線で、16x16 ピクセルの中に描きます(最小化は「−」、最大化は「□」、元に戻すは 2 つの重なった四角)。ポインターを乗せると、地の色を少し明るくします。押して、そのボタンの上で離すと働きます(外へ出して離すと、取り消し。閉じるボタンと同じ)。

最大化:

- 最大化のボタンか、タイトルバーのダブルクリック(同じウィンドウのタイトルバーを、500 ミリ秒の中で、4 ピクセルより近い所でもう一度押す)で、最大化と元に戻すを切り替えます。
- 最大化すると、外枠の左上を使える範囲の左上に置き、使える範囲からタイトルバーの高さを引いた大きさを、maximized の状態つきの configure で伝えます(タスクバーがあれば、その上まで)。
- 使える範囲が変わったら(タスクバーが出た・去ったなど)、最大化しているウィンドウには、新しい範囲の大きさを configure で伝え直し、新しい範囲の左上へ置きます。
- 元に戻すと、最大化する前の大きさ(そのとき描いていたコンテンツの大きさ)を、maximized を外して伝えます。位置は、スロットにあったウィンドウは、いまの使える範囲のそのスロットへ、動かされていたウィンドウは、前の位置へ(タイトルバーが使える範囲に入るようにして)戻します。
- 最大化している間は、サイズ変更の境界がありません。クライアントからのサイズ変更の頼みも受けません。クライアントからの移動の頼み(xdg_toplevel の move)は、タイトルバーを grab したときと同じに、元の大きさに戻して動かします(下の「ドラッグで戻す・上端で最大化する」)。
- 最大化しているウィンドウのタイトルバーを grab して、8 ピクセル動かすと、元の大きさに戻し、そのまま動かします(下の「ドラッグで戻す・上端で最大化する」)。

ドラッグで戻す・上端で最大化する:

- 最大化しているウィンドウのタイトルバーを grab して、押した点から 8 ピクセル(ふつうの移動のドラッグのしきい値の 4 ピクセルの 2 倍)動かすと、元の大きさに戻し(maximized を外した configure)、そのまま移動を続けます。
  - 置く所:ポインターが、元の大きさのタイトルバーの、横の同じ割合の所に来るようにします。たとえば、最大化しているタイトルバーの左から 1/4 の所を grab していたら、元の大きさのタイトルバーの左から 1/4 の所。ただし、ボタン(閉じる・最大化・最小化)の上には来ないように、ボタンの左の端の 1 つ手前までに寄せます。縦は、grab したときのタイトルバーの中の高さのままです。
  - 戻したウィンドウは、スロットの番号を持ちません(動かしたウィンドウと同じ)。
  - 8 ピクセルにしたのは、ダブルクリックとの関係からです。ダブルクリックの 2 回目は、1 回目の押下から 4 ピクセルの中で押す決まりなので、ダブルクリックのつもりで 1 回目に 4 ピクセル程度ずれても、ウィンドウが元の大きさに戻って動き出さないようにします。元に戻すとウィンドウの大きさと位置が大きく変わるので、ふつうの移動(4 ピクセル)より、はっきり動かしたときだけにしています。
  - 8 ピクセルの手前で離したときは、何もしません(クリックとダブルクリックは、今までどおり)。ダブルクリックの 2 回目の押下のまま動かしても、動かしません。
- 動かしている最中に(タイトルバーを grab したときも、クライアントから頼まれた移動のときも)、ポインターが使える範囲の上端に触れたら(y が使える範囲の上端以下)、最大化の予告として、使える範囲の内側に沿った太さ 2 ピクセルの枠と、その内側の薄い面(どちらも選んだものの色 `#f09311`。面は不透明度 0.12。切り替えの一覧の強調と同じ色)を、ウィンドウより手前に描きます。そこで離すと最大化します。上端から離れたら、予告を消します。予告を取り消すキー(Esc)はありません。
- 大きさの決まったウィンドウ(最大化のボタンを出していないもの)では、予告を出さず、上端で離しても最大化しません。
- どちらの操作でも、ふつうの最大化・元に戻すと同じ道を通るので、foreign-toplevel(タスクバー)の maximized の状態も合います。重なる順、activated、キーボードのフォーカスは、押したときの raise のほかには動きません。
- クライアントから頼まれた移動(xdg_toplevel の move。自分でタイトルバーを描くアプリが、そこを押されたときに頼む)でも、同じに扱います。最大化しているウィンドウでは、押した点から 8 ピクセル動いた所で元の大きさに戻し、移動を続けます。置く所の横は、上と同じ計算(押した点の、外枠の横の割合)で、縦は、押した点の、外枠の上からの高さのままです(元の大きさの外枠に入るように寄せる)。上端での最大化の予告も、同じに出します。頼みが届くまでにポインターが 8 ピクセルより多く動いていたら、頼みを受けた所で戻します。
- 大きさの決まったウィンドウ(クライアントの最小と最大の大きさが同じ)には、最大化のボタンを出さず、最大化しません。
- クライアントからの頼み(xdg_toplevel の `set_maximized`・`unset_maximized`)にも応えます。応じないときも、configure を返します。

最小化:

- 最小化のボタンは、戻す手段があるときだけ出します。戻す手段とは、foreign-toplevel の manager を bind しているシェルの部品(タスクバーなど)です(`docs/adr/0002-shell-components.md`)。
- 最小化したウィンドウは描かず、ポインターもヒットしません。activated は、最小化していないうちの、いちばん手前のウィンドウへ移ります。frame callback も返しません。重なる順は変えません。
- 戻すのは、シェルの部品からです(foreign-toplevel の activate か unset_minimized)。戻したウィンドウは、raise して activated にします。
- シェルの部品が 1 つも無くなったら、戻す手段が無くなるので、最小化しているウィンドウを全部戻し、最小化のボタンも消します。
- クライアントからの頼み(xdg_toplevel の `set_minimized`)にも応えます。戻す手段が無いときは、何もしません。

できること(xdg_toplevel の `wm_capabilities`):

- いつも maximize を、シェルの部品があるときは minimize も、クライアントに伝えます(バージョン 5 以上の `xdg_wm_base` を使うクライアントに、ウィンドウを作ったときに届きます)。全画面とウィンドウメニューは、伝えません。

## activated なウィンドウ

いちばん手前のウィンドウが、activated なウィンドウです。クライアントには、xdg_toplevelの `activated` の状態として、configureで知らせます。

- `activated` が付くのは、いつも、いちばん手前の1つだけです。
- 新しいウィンドウをつないだとき:新しいウィンドウに付き、前に手前だったものからは外れます。新しいウィンドウには、最初のconfigureで一緒に知らせます。
- クリックで raise したとき:出したウィンドウに付き、前に手前だったものからは外れます。
- いちばん手前のウィンドウが去ったとき:その下にあったものに付きます。
- 奥のウィンドウが去ったとき:何も変わりません。
- 知らせるのは、状態が変わったウィンドウにだけです。変わらないウィンドウには、configureを送りません。

キーボードのフォーカスは、`activated` のウィンドウに付きます(下の「キーボード」)。
Seinasが描くタイトルバーも、activated なウィンドウだけ、色が違います。

## キーボード

seat にキーボードがあります(入れ子の構成と、テスト用の入力インターフェースを開いた seinas-standalone)。

- キーボードのフォーカスは、`activated` のウィンドウ(最小化していないうちの、いちばん手前のウィンドウ)で、絵を出しているものに付きます。そのようなウィンドウが無ければ、どこにも付きません。
- フォーカスは、新しいウィンドウが絵を出したとき、raise したとき、foreign-toplevel の activate のとき、最小化したとき・戻したとき、ウィンドウが閉じたときに、移ります。変わったときだけ、前のウィンドウに leave、新しいウィンドウに enter を送ります。
- 押した・離したキーと、修飾キーの状態は、フォーカスのあるクライアントへ届きます。最小化したウィンドウには、フォーカスが無いので届きません。
- フォーカスの先は、次の順に決めます:grab しているポップアップの連なりのいちばん上(下の「ポップアップ」)、exclusive の top か overlay の layer surface、押してフォーカスを受けた on_demand の layer surface、`activated` のウィンドウ(上の「layer surface と使える範囲」)。
- text-input(IME)のフォーカスは、キーボードのフォーカスに付いていきます(`docs/ime.md`)。
- keymap:
  - 入れ子の構成:親の `wl_keyboard` から届いた keymap を、そのままクライアントへ配ります。親の keymap が届くまでは、xkbcommon の既定の keymap です。親のキーボードのフォーカスが外れたら、押されているキーを、全部離したことにします(クライアントで繰り返しが続かないように)。押されている修飾キー(Shift、Alt など)は、親から届くものではなく、キーから Seinas が求めます。固定された修飾キー(Caps Lock、Num Lock)は、親から届く状態(wl_keyboard の modifiers の mods_locked)に合わせます。合わせたときは、フォーカスのあるクライアントへ、leave と enter で伝え直します(Smithay に、修飾キーの状態だけを送り直す手段が無いため)。押されている修飾キーを親から受けないのは、押したことが届いていないキーを押されたことにすると、離したことも届かず、押されたまま残るためです。
  - 親のいない構成(seinas-standalone、fbdev):日本語の配列(xkb の layout `jp`、model `jp106`)。xkb のファイル(既定は `/usr/share/X11/xkb`。`XKB_CONFIG_ROOT` で変えられる)が要ります。keymap を作れなければ(xkb の置き場そのものが無いときも、ファイルが足りないときも)、ログ(`no keyboard: the keymap could not be made: …`)に出して、キーボードの無い構成として動きます。IME の global も作りません(`docs/ime.md`)。
  - 押し続けたときの繰り返しは、600 ミリ秒の後に 1 秒あたり 25 回(入れ子では、親の設定)。繰り返しは、クライアントが行います。
- Seinas のショートカット:キーは、IME とクライアントへ渡す前に、Seinas のショートカットの判定を通ります(`docs/adr/0004-ime-keyboard-path.md`)。Seinas が使ったキーは、離したことも、どこへも渡しません。一覧は、ウィンドウの切り替え(既定は Alt+Tab と Alt+Shift+Tab。入れ子の構成では Alt+F6 と Alt+Shift+F6 も。`seinas.conf` で変えられる。下の「Alt+Tab」)と、切り替えの最中の Esc(取り消し)と、IME の緊急解除(既定は Alt+Shift+F12。`docs/ime.md` の「IME の復旧」)だけです。

## ポップアップ

ポップアップ(xdg_popup。右クリックのメニュー、コンボボックスの一覧、ツールチップなど)は、xdg-shell の決まりに従って扱います。

置き方:

- 位置と大きさは、クライアントが xdg_positioner で頼んだもの(anchor rect、anchor、gravity、offset、大きさ)です。親は、ウィンドウか、ほかのポップアップか、layer surface(`zwlr_layer_surface_v1.get_popup`)です。
- 画面からはみ出すときは、positioner の constraint_adjustment(反転、ずらし、縮め)を、決まりの順(反転、ずらし、縮め)で使い、収めます。計算は Smithay(`PositionerState::get_unconstrained_geometry`)に任せます。収める枠は、ウィンドウのポップアップでは使える範囲(タスクバーなどの exclusive zone を除いた所)、layer surface のポップアップでは画面の全体(タスクバー自身は、使える範囲の外にあるため)です。constraint_adjustment が無ければ、はみ出したまま置きます。
- 置き直しの頼み(xdg_popup.reposition。xdg_wm_base のバージョン 3)は、新しい positioner で置き直し、repositioned と configure を送ります。

描き方:

- ポップアップは、根元(いちばん下の親。ウィンドウか layer surface)のすぐ手前に描きます。入れ子のポップアップは、親のポップアップの手前です。
- Seinas の飾り(タイトルバー、枠、影、角丸)は付けません。根元のウィンドウの角丸のクリップにも掛けません(ウィンドウの外へはみ出す所も描きます)。
- 描いたら、ウィンドウと同じく、ポップアップ(入れ子のものも)に frame コールバックを返します(返さないと、GTK などは次の絵を描かず、メニューの強調が変わりません)。
- ポインターは、手前に描くものから順に当てます。ポップアップの上では、根元のウィンドウより先に、ポップアップが受け取ります(入力の範囲は、面の大きさと input region。サブサーフェスを含む)。ポップアップの上でのボタンは、ウィンドウを raise したり動かしたりしません。

grab(xdg_popup.grab):

- seat が Seinas のもので、serial が直前の入力(クライアントへ渡したポインターの押下か、キーの押下。新しいものから 8 つ)のものなら、受けます。そうでなければ、すぐ popup_done を送ります(決まりの「the compositor may deny the grab」)。最初の commit の後の grab と、いちばん上でないポップアップを親にした grab は、プロトコルのエラーにします。
- grab の間は、キーボードのフォーカスを、連なりのいちばん上のポップアップに付けます(Esc などのキーも、そのポップアップへ渡ります。閉じるかは、クライアントが決めます)。連なりが閉じたら、元のフォーカスに戻します。
- grab の間、ポインターは、grab したクライアントの面にだけ渡します(決まりの owner-events。同じクライアントのウィンドウの上でも渡り、閉じません)。ほかの所(ほかのクライアントの面、Seinas のタイトルバー、何も無い所)を押したら、連なりを、上のポップアップから順に閉じます(popup_done)。その押下と、対になる離す側は、どこへも渡しません。
- 次のときも、連なりを閉じます:Alt+Tab で切り替えを始めたとき、ウィンドウを動かす修飾キー(`window-drag`)を押しながらボタンを押したとき(閉じてから、ふだんどおりに動かす・サイズ変更を始める)、ほかのウィンドウが activated になったとき。
- grab の無いポップアップ(ツールチップなど)は、Seinas からは閉じません。閉じるのは、クライアントです。

## クリップボードとドラッグ&ドロップ

wl_data_device_manager(バージョン 3)を出します。仕組みは Smithay(`DataDeviceState`)に任せます。GTK 3 は、これが無いと wl_seat を使わず、キーもポインターも受け取りません。

クリップボード(selection):

- selection を見せる相手は、キーボードのフォーカスのあるクライアントです。フォーカスが移るたびに、移った先のクライアントに、今の selection を見せます。フォーカスが無くなったら、だれにも見せません。
- フォーカスの無いクライアントは、selection を受け取れず、置くこと(set_selection)もできません(Smithay が断ります)。
- 中身は、クライアントどうしがパイプで運びます(貼り付ける側が作ったパイプの書き口を、コンポジタがコピーした側へ送り直します)。Seinas は中身を読みません。
- primary selection(中ボタンの貼り付け)は、まだありません。

ドラッグ&ドロップ(クライアントどうし):

- start_drag は、そのクライアントへ渡した押下のボタンを押している間だけ、その押下の serial で受けます(Smithay が、押しているボタンの暗黙の grab の serial かを確かめます)。
- 最中のポインターのイベントは、Seinas の操作(タイトルバー、サイズ変更の境界、修飾キーとドラッグ)にも、ポップアップの grab(ほかのクライアントの面に渡さない決まり)にも使わず、そのまま渡します。ポップアップの連なりは閉じません(ポップアップから始めたドラッグも、ほかのクライアントへ落とせます)。Seinas のタイトルバーや何も無い所の上は、どのクライアントの上でもない扱いです。
- 全部のボタンを離したら、上にいるクライアントが受け入れていれば落とし、受け入れていなければ取り消します。
- アイコン(クライアントが渡した面)は、ポインターの位置に、いちばん手前に描きます。
- Smithay 0.7.0 は、受け入れた型を、ドラッグした側に知らせません(wl_data_source.target を送りません。動作(action)は知らせます)。

## Alt+Tab

Alt を押したまま Tab を押すと、ウィンドウを切り替えます。

- キー:既定は、次へが Alt+Tab、前へが Alt+Shift+Tab です。入れ子の構成(`seinas`)では、Alt+F6 と Alt+Shift+F6 も使います(WSLg では、Alt+Tab を Windows が先に使い、Seinas まで届かないため。Windows が使わない環境もあるので、Alt+Tab も残します)。ZeikOS の上(QEMU・実機)では、間に入るものが無いので、Alt+Tab を使います。キーは `seinas.conf` の `switch-next`・`switch-prev` で変えられます(`docs/config.md`)。どのキーでも、下の動き(順、取り消し、最小化、決める)は同じで、修飾キーを押したまま F6 を続けて押すと、順に進みます。
- 決めるのは、切り替えを始めたキーの修飾キー(Shift を除く。既定では Alt)を離したときです。Shift のほかに修飾キーの無いキーを設定したときは、押すたびに 1 つ進んで、その場で決めます。

- 順:activated のウィンドウを先に、ほかを重なる順(手前から)に並べた順で、Tab ごとに次へ進みます。Alt+Shift+Tab は、逆の順です。端では、反対の端へ回ります。ウィンドウは activate したときに raise するので、重なる順は、最後に activated になった順(MRU)と同じです。最小化しても重なる順は変わらないので、activated のウィンドウだけを先に出します。
- 候補:切り替えを始めたときの、絵を出しているウィンドウです。最小化しているウィンドウも入ります。途中で出たウィンドウは入りません。途中で閉じたウィンドウは外し、見せていた候補が閉じたら、次の候補を見せます。候補が無くなったら、切り替えは終わります。
- 見せ方:候補のウィンドウを、いちばん手前に描きます(最小化していても描きます)。ポインターも、候補にヒットします。
- 一覧:切り替えを始めたら、出力の中央に、候補の一覧を出します。決めたとき・取り消したときに消します。コンポジタの中で描きます(シェルの部品にしない理由は ADR 0002 の 9b)。
  - 候補を、切り替えの順(使った順)に 1 行ずつ並べ、今の候補の行を、選んだものの色(`#f09311`)の 2 ピクセルの枠と、控えめな地(`#38322e`)で強調します(文字の色は変えません)。
  - タイトルは、タイトルバーと同じフォントと大きさで描きます。幅に収まらなければ、末尾を切って「…」を付けます。タイトルの無いウィンドウは「(タイトルなし)」と書きます。
  - 最小化しているウィンドウは、行の左に「−」の印を付け、タイトルを暗い色で書きます。
  - 幅は 480 ピクセルまでで、出力が狭ければ、出力の幅から両側の 16 ピクセルを引いた幅にします。高さは、上下の余白 8 ピクセルと、1 行 28 ピクセルの行の数です。
  - 行は、出力の高さに入るだけ(両側の 16 ピクセルと余白を引いて)、9 行までです。候補がそれより多いときは、今の候補が見える範囲だけを出し、上と下に、隠れた候補の数を「▲ ほか N 件」「▼ ほか N 件」の行で出します。今の候補は、できるだけ中ほどに来るようにし、端に近いときは端からそろえます。出力が低く 3 行も取れないときは、今の候補の 1 行だけを出します。いちばん小さい出力(320x240)では 6 行です。
  - 途中で候補が閉じたら、一覧からも外します。一覧の項目をポインターで押して選ぶことは、できません(切り替えの最中にポインターのボタンを押すと、取り消します)。
- 決める:Alt を離すと、候補を raise して activated にし、キーボードのフォーカスを移します。最小化していたウィンドウは戻します。
- 取り消す:Esc を押すと、候補を見せるのを止めます。重なる順とフォーカスは、始める前のままです。切り替えの最中にポインターのボタンを押したときと、入れ子の構成で親のキーボードのフォーカスが外れたときも、取り消します。
- ウィンドウが 1 つなら、そのウィンドウのままです。ウィンドウが無ければ、何も起きません。
- 切り替えの間は、activated(xdg_toplevel の状態と foreign-toplevel)とキーボードのフォーカスを動かしません。候補ごとに activated を送ると、クライアントが候補ごとに再描画し、キーボードの leave と enter(IME の切り替えも)が続き、取り消したときにも元へ送り直すことになるためです。決めたときに、1 回だけ送ります。見せている候補のタイトルバーは、activated でない色になります。
- キー:
  - Seinas が使った切り替えのキー(Tab、F6 など)と Esc は、押したことも離したことも、クライアントへ渡しません。切り替えの間のほかのキー(修飾キーを除く)も、渡しません。
  - Alt と Shift などの修飾キーは、フォーカスのあるクライアントへ渡します。Alt を離したことは、先にフォーカスのあるクライアントへ渡し、その後でフォーカスを移します。フォーカスが移った先のクライアントへの enter には、そのときに押されているキー(クライアントへ渡したもの)と修飾キーの状態が入ります。どちらのクライアントにも、Alt が押されたまま残りません。
- 入れ子の構成(WSLg)で物理的なキーで確かめたところ、Alt+Tab は Windows が先に使い、Seinas には届きませんでした(2026-10-13)。そのため、入れ子の構成では Alt+F6 を足しました。Alt+F6 が届くかは、まだ確かめていません。届かなければ、`--log-keys` で届く組み合わせを確かめて、`seinas.conf` で変えます(`docs/config.md`)。

## 置き方

スロットには、0から順に番号が付いています。スロットは、タイトルバーを含めた外枠の左上の位置です。
コンテンツは、そこからタイトルバーの高さ(36ピクセル。Seinas が飾りを描かないウィンドウは 0)だけ下に来ます。
位置は、使える範囲(上の「layer surface と使える範囲」)の左上を基準にします。exclusive zone を持つ layer surface が無ければ、画面の左上です。

| 番号 | 外枠の左上の位置(使える範囲の左上からのずれ。ピクセル) |
| --- | --- |
| 0 | (0, 0) |
| 1 | (32, 32) |
| 2 | (64, 64) |
| n | (32 × n, 32 × n) |

- 新しいウィンドウは、空いている中で、いちばん小さい番号のスロットに入ります。
  1つ目は左上、2つ目はそこから右と下へ32ピクセルずつずれた所、という並びになります。
- ウィンドウが去ると、その番号は空きます。次のウィンドウは、空いた番号に入ります。
  たとえば、ウィンドウが1つだけのときは、何度つなぎ直しても左上に出ます。
- 置いたウィンドウの位置は、動かされるまで変わりません。
- 動かしたウィンドウは、スロット番号を手放します。その番号は空き、次の新しいウィンドウが使えます。
  動かしたウィンドウの位置は、そのウィンドウが去るまで保ちます。
- タイトルバーを押しただけ(4ピクセルのしきい値の中で離した)のウィンドウは、動いていないので、番号を持ったままです。
- 少しだけ動かしたウィンドウの上に、新しいウィンドウが重なることがあります。空いている所を探して置くことは、していません。
- ずらす量(32ピクセル)は、タイトルバーの高さ(24ピクセル)より大きくしてあります。奥のウィンドウのタイトルバーは、手前のウィンドウに隠れず、タイトルの頭の部分が読めます。

## 折り返し

スロットの数には、限りがあります。外枠の左上が、使える範囲の短い辺の半分を超えないように決めています。

- スロットの数は「短い辺 ÷ 2 ÷ 32」(端数は切り捨て。少なくとも1つ)です。
  800x600なら9つ(最後は(256, 256))、640x480なら7つ(最後は(192, 192))です。
- スロットが全部ふさがっているときは、番号0から順に、もう一度使います(すでにあるウィンドウと同じ位置に、手前に重なります)。
- ウィンドウの大きさは、スロットを決めるときには見ていません。大きなウィンドウは、画面の右や下にはみ出すことがあります。はみ出した分は、描かれません。
- タイトルバーは、いつも外枠のいちばん上にあるので、どのスロットでも、タイトルバーの全体が画面の中に入ります(幅が画面より広いウィンドウを除く)。

## 大きさ

新しいウィンドウの最初の configure では、大きさを 0x0 にして、クライアントに任せます(2026-10-26。運用者の決定。重ねて使う画面では、アプリが自分の大きさで開くのがふつうのため。前は、使える範囲いっぱいを伝えていて、GTK などが画面いっぱいで開いていました)。

- 開いた(最初の絵を出した)ウィンドウの大きさが、使える範囲より大きいときは、範囲に収まる大きさ(使える範囲の大きさからタイトルバーの高さを引いたもの。はみ出した向きだけ縮める)を configure で伝え直します。1 回だけで、それに従うかどうかは、クライアントしだいです。exclusive zone が無い 640x480 なら 640x444 まで、下に高さ 40 のタスクバーがあれば 640x404 までです。
- 置く位置は、置き方の決まり(上の「置き方」)のままです。
- 最大化・全画面の configure では、今までどおり大きさを伝えます(使える範囲から、タイトルバーの高さを引いたもの)。タイル状態は、まだありません。
- 自作のクライアントは、どれも最初の configure の大きさに従いません。zeyes-min はいつも 320x240、テスト用のクライアント(`test-client window`)は `--size` の大きさ(既定は 200x150。`--follow-size` でも、最初の configure には従わない)、`test-client shrink` は 400x300 で描きます。

## 出力の大きさが変わったとき

入れ子の構成では、親のウィンドウの大きさを変えると、中の画面(出力)の大きさも、それに合わせて変わります。テスト用の入力インターフェースの `output WxH` の行(`standalone.md`。fake screen のときだけ)も、同じ道を通ります。

- 親のウィンドウ:最初は 800x600 で開きます。親の xdg_toplevel の configure で大きさが届いたら、その大きさにします(大きさの指定が無い configure では、今のまま)。小さすぎるとタイトルバーとタスクバーが入らないので、下限を 320x240 にしています(親へ `set_min_size` で伝え、それより小さな指定は 320x240 にする)。上限は置きません。
- 出力:wl_output のモード(大きさ)を送り直します(xdg-output の論理の大きさも、一緒に送られる)。前の大きさのモードは、これからつなぐクライアントには見せません(大きさを変え続けても、モードが溜まらない)。xdg-output の global は、どのクライアントにも見せます(SCTK のクライアントは、これで出力の論理の大きさを知る)。
- layer surface:並べ直し、大きさの変わった layer surface(壁紙、タスクバー)に configure を送ります。壁紙は再描画し、タスクバーは新しい下の端に移ります。
- 使える範囲を求め直し、ウィンドウを新しい範囲に合わせます(上の「layer surface と使える範囲」と同じ決まり)。
  - 最大化しているウィンドウには、新しい範囲の大きさを configure で伝え、範囲の左上に置きます。
  - スロットにあるウィンドウは、新しい範囲の同じスロットへ移します。
  - 動かされたウィンドウは、タイトルバーが範囲に入るように戻します(動かすときの限りと同じ。右には 48 ピクセル、左には 120 ピクセル残し、上下はタイトルバーが入る所まで)。小さくして画面の外に出たウィンドウも、これで手が届く所へ戻ります。
- ドラッグの間の工夫:親のウィンドウの大きさを変えている間、親は configure を続けて送ってきます。届くたびに合わせるのではなく、最後に届いた大きさだけを覚えておき、次に親へ絵を出すとき(親の frame callback で、出してよくなったとき)に合わせます。こうすると、出力を変える回数(クライアントへの configure と、壁紙などの再描画、共通のレンダラーの作り直し)が、親へ絵を出す回数(1 秒に 60 回まで)を越えません。止まって待つ(一定の時間、変わらなくなるまで合わせない)形にはしていません。ウィンドウの大きさに中の画面が遅れて付いてくるように見えるのを避けるためです。
- 同じ大きさが届いても、何もしません。

## ポインター(入れ子の構成)

入れ子の構成では、ポインターの下にある、いちばん手前のウィンドウへ、ポインターの動きを渡します。
座標は、そのウィンドウのコンテンツの左上を原点にして渡します。どのウィンドウの上でもなければ、どこにも渡しません。
ポインターがタイトルバーの上にあるときも、どこにも渡しません(タイトルバーはSeinasのものです)。
コンテンツの上でボタンを押している間は、ポインターが外へ出ても、離すまで、そのウィンドウへ渡し続けます。
ウィンドウを動かしている間と、閉じるボタンを押している間は、どこにも渡しません。

フロントエンドとfbdevの構成は、入力の装置を扱いません。テスト用の入力インターフェース(`--test-input`。`standalone.md`)を開いたときだけ、同じ決まりで働きます。

## テスト

- スロット番号の決め方と折り返し、押した所のウィンドウの選び方、raise したときの順とスロット、`activated` が手前の1つだけに付くことは、`crates/seinas-frontend` のユニットテスト(`src/stack.rs`)で確かめています。
- `activated` のイベントが実際に届くことは、`crates/seinas-standalone/tests/activation.rs` が確かめます。テスト用のクライアント(`test-client window`)が、届いたconfigureの中身を書き出し、それを読みます。
- 実際の重なり方と位置は、`crates/seinas-standalone/tests/stacking.rs` が、色の違う2つのzeyes-minを fake screen につないで、ピクセルで確かめます。
  zeyes-minの目のまわりの色は、引数 `--skin RRGGBB` か、環境変数 `ZEYES_SKIN` で変えられます(既定は緑)。
  あわせて、タイトルバーの色が、手前のウィンドウと奥のウィンドウとで違うことも確かめます。
- タイトルバーは、`crates/seinas-standalone/tests/title.rs` が、ピクセルで確かめます。確かめるのは、タイトルバーがあること、タイトルの位置に文字のピクセルがあること、タイトルを変えると描き直されること、activated かどうかでタイトルバーの色が違うこと、タイトルが無いときの表示、長いタイトルを切ること、フォールバックのフォントでの表示、どのフォントにも無い文字の枠、フォントが無い・壊れているときに止まらないこと、xdg-decorationの答えです。
  テスト用のクライアントは、`test-client window --title TEXT` でタイトルを、`--app-id TEXT` でapp_idを付けられます。標準入力へ `title TEXT` の行を送ると、タイトルを変えます。

## まだ無いもの

IME の道(text-input-v3、input-method-v2、virtual-keyboard の取り次ぎ)はあります(`docs/ime.md`)が、IME そのもの(Kieli)は、まだありません。今つなげるのは、テスト用の IME です。
IME が virtual-keyboard で送ってきたキーの serial は、Seinas からは分からない(Smithay の中で作られる)ため、その serial でのポップアップの grab は受けません(すぐ popup_done を送ります)。
クリップボードの primary selection(中ボタンの貼り付け)と、コンポジタから始めるドラッグ&ドロップは、ありません。ドラッグ&ドロップのアイコンを描くことは、自動のテストでは確かめていません。
全画面は、できません。画面の左右の端へのドラッグで半分の大きさにする(Windows のスナップ)ことも、できません。
応答なしのクライアントのプロセスを止める(kill する)仕組みは、ありません(上の「応答なし」)。ping は、閉じるように頼んだときにだけ送り、いつも見張ることはしていません。
クライアントが装飾のオブジェクトを消したこと(`destroy`)は、Seinas には分かりません(上の「飾りを描く側の取り決め」)。
