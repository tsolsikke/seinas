# ウィンドウの重ね方と置き方

クライアントのウィンドウ(toplevel)を、どの順に重ね、どこに置くかの決まりです。
受け口(`crates/seinas-frontend` の `src/stack.rs`)で決めているので、入れ子の構成(`seinas`)でも、受け口とfbdevの構成(`seinas-standalone`)でも、同じに振る舞います。

## 題名の帯と、ウィンドウの外形

どのウィンドウにも、Seinasが、上に題名の帯(タイトルバー)を付けます。

- 帯の高さは24画素で、幅は、クライアントが描く中身と同じです。中身は、帯のすぐ下に置きます。
- 帯と中身を合わせたものを、ウィンドウの「外形」と呼びます。中身が320x240なら、外形は320x264です。
- 置き場所や、押した所の当たり判定は、外形で決めます。
- まだ絵を出していないウィンドウ(大きさが無い)には、帯も付けません。

帯に出すもの:

- クライアントが付けた題名(xdg_toplevelの `set_title`)を、左に寄せて出します。左右の端から8画素ずつ空けます。
- 題名が無い(または空白だけの)ときは、app_id(`set_app_id`)を出します。それも無ければ、帯だけを出します。
- 帯の右の端には、閉じるボタンがあります(下の「閉じる」)。題名は、その手前に収めます。
- 収まらない題名は、末尾を切って「…」を付けます。
- 題名やapp_idが変わると、帯を描き直します。
- 文字の大きさは14画素で、フォントはBIZ UDPゴシックです。このフォントに無い文字は、控えのGNU Unifont JPで描きます。どちらにも無い文字は、四角の枠で描きます(`docs/text-rendering.md`)。
- フォントのファイルが読めないときは、帯だけを描き、原因をログに出します。Seinasは止まりません。

帯の色:

| ウィンドウ | 帯の色 | 題名の色 |
| --- | --- | --- |
| 選ばれている(いちばん手前) | 青(`#2f6fb5`) | 白(`#ffffff`) |
| 選ばれていない | 灰色(`#4a505c`) | 明るい灰色(`#c8ccd4`) |

飾りを描く側の知らせ(xdg-decoration):

- Seinasは `zxdg_decoration_manager_v1` を公開しています。クライアントが飾りの描き方を尋ねると、いつも「サーバーの側(Seinas)で描く」と答えます。クライアントが「自分で描きたい」と頼んでも、同じ答えを返します。
- このプロトコルを使わないクライアントにも、帯は付けます。自分で題名の帯を描くクライアントでは、帯が二重に見えます。

## layer surface と使える範囲

タスクバー・メニュー・デスクトップは、コンポジタの外の別のプログラム(シェルの部品)として作ります(`docs/adr/0002-shell-components.md`)。
シェルの部品は、wlr-layer-shell(`zwlr_layer_shell_v1`、バージョン 4)で、layer surface を出します。

- layer-shell の global は、シェルの部品のためのソケット(ふだんのソケットのパスに `-shell` を付けたもの。入れ子の構成では `seinas-0-shell`)からつないだクライアントにだけ見えます。ふだんのソケットのクライアントには、global そのものが見えません。
- 層は、奥から background、bottom、(通常のウィンドウ)、top、overlay の順に重なります。同じ層の中では、後から出た layer surface が手前です。
- 位置と大きさ(anchor、margin、exclusive zone、頼んだ大きさ)の計算は、Smithay の `LayerMap` に任せています。layer surface の commit のたびに並べ直し、最初の commit で最初の configure を送ります。
- 画面は 1 つなので、layer surface が output を指定しても、見ません。

使える範囲(usable area):

- 使える範囲は、画面から、layer surface の exclusive zone を除いた矩形です。exclusive zone を持つ layer surface が無ければ、画面の全体です。
- 新しいウィンドウのスロット、configure で伝える大きさ、ドラッグで外へ出せる範囲は、使える範囲を基準にします(下の「置き方」「大きさ」「動かす」)。最大化を入れるときも、使える範囲を基準にします。
- 使える範囲が変わったとき(exclusive zone を持つ layer surface が出た・去った・変わった)は、スロットにあるウィンドウを新しい範囲の同じスロットへ移し、動かされたウィンドウは、タイトルバーが新しい範囲に入るように動かします。すでに configure で伝えた大きさは、送り直しません。

ポインター:

- ボタンを押していない間は、top と overlay の layer surface が、ウィンドウより先にポインターのイベントを受け取ります。その上でボタンを押しても、下のウィンドウは raise されず、ドラッグや close ボタンも働きません。
- ウィンドウの上でない所では、bottom と background の layer surface が、ポインターのイベントを受け取ります。
- キーボードの入力(`keyboard_interactivity`)は、まだ扱っていません(どの値でも、キーボードの入力を渡しません)。メニュー(トーチ)を作るときに扱います。

## ウィンドウの一覧と操作(foreign-toplevel)

タスクバーなどのシェルの部品に、ウィンドウの一覧と、ウィンドウを操作するプロトコルを見せます(`docs/adr/0002-shell-components.md`)。

- 公開するのは、wlr-foreign-toplevel-management(`zwlr_foreign_toplevel_manager_v1`、バージョン 3)と、ext-foreign-toplevel-list(`ext_foreign_toplevel_list_v1`、バージョン 1。読むだけの一覧)の 2 つです。どちらの global も、layer-shell と同じく、シェルの部品のためのソケットからつないだクライアントにだけ見えます。
- 一覧に載るのは、絵を出した(map した)ウィンドウだけです。一覧の順は map した順で、スタックの順とは別です。絵を外したウィンドウは、一覧から外れます(closed)。
- 送る内容は、タイトル・app_id(付けていなければ送らない)、output(output_enter。output は 1 つで、wl_output を後から bind したクライアントには、そのときに送る)、状態です。状態は、いちばん手前のウィンドウに付く activated だけです(最大化・最小化・全画面は、まだ持っていません)。タイトル・app_id・状態が変わるたびに、変わったものと done を送ります。ウィンドウが去ったら closed を送ります。
- 頼みの扱い:
  - activate:そのウィンドウを raise して、activated にします(クリックで raise したときと同じ)。seat の指定は見ません。
  - close:クライアントに、閉じるように頼みます(閉じるボタンと同じ)。応じるかどうかは、クライアントしだいです。
  - set_maximized・unset_maximized・set_minimized・unset_minimized・set_fullscreen・unset_fullscreen:受けますが、今は何もしません(状態も変えません。ログに 1 行出します)。最大化と最小化は、ウィンドウの最大化・最小化を入れるときに扱います。
  - set_rectangle:受け取って覚えるだけです(最小化のアニメーションの行き先に使えますが、今は使いません)。幅か高さが負なら、プロトコルのエラー(invalid_rectangle)で切ります。
  - stop:finished を送り、それからは新しいウィンドウを送りません。前から持っている handle には、変化を送り続けます。
- 閉じたウィンドウの handle への頼みは、何もしません。

## 重ね方

- 新しくできたウィンドウは、いちばん手前に来ます。
- ウィンドウが去ると、その下にあったものが見えるようになります。残ったウィンドウどうしの順は変わりません。

## クリックで手前に出す

ポインターのボタンを押すと、押した所にある、いちばん手前のウィンドウが、いちばん手前に出ます。

- 出るのは、押した所で見えているウィンドウです。奥のウィンドウは、見えている端(手前のウィンドウに隠れていない所)を押すと出せます。題名の帯を押しても、同じです。
- ほかのウィンドウどうしの順は、変わりません。
- 置き場所(位置と、置き場所の番号)は、変わりません。重なる順だけが変わります。
- すでにいちばん手前のウィンドウを押したときは、何も変わりません。
- どのウィンドウの上でもない所を押したときは、何も変わりません。
- どのボタンでも同じです。
- 中身を押した知らせ(button)は、手前に出したウィンドウへ、いつもどおり渡します。手前に出すだけで、知らせを消しません。帯を押した知らせは、クライアントには渡しません。
- まだ絵を出していないウィンドウ(大きさが無い)には、当たりません。

受け口とfbdevの構成(`seinas-standalone`)は、入力の装置を扱わないので、ふだんの起動では、ポインターでの操作(手前に出す、動かす、閉じる)が働きません。決まりそのものは、同じものを持っています。

## 動かす

題名の帯を、左のボタンで掴んで動かすと、ウィンドウが付いてきます。

- 掴めるのは、帯のうち、閉じるボタンを除いた所です。押した時点で、そのウィンドウは手前に出ます。
- 押してから4画素動くまでは、動かしません。手前に出すだけのつもりで押したときに、ずれないようにするためです。
  4画素を超えると動き始め、その後は、押した点からのずれのぶんだけ、ちょうど動きます(遊びのぶんも含みます)。
- ボタンを離すと、終わります。
- 動かしている間、ポインターの知らせは、どのクライアントにも渡しません。
- 左でないボタンで帯を押したときは、手前に出すだけです。
- 動かしている間に、そのウィンドウが去ったときは、何も動かさずに終わります。

画面の外へ出せる範囲には、限りがあります。帯を、もう一度掴めるようにするためです。
限りは、使える範囲(画面から、タスクバーなどの exclusive zone を除いた矩形)を基準にします。タスクバーの下に、帯が隠れないようにするためです。

| 向き | 限り |
| --- | --- |
| 上 | 帯の上の端は、使える範囲の上の端より上へ行かない |
| 下 | 帯の全体が、使える範囲の中に残る(中身は、その下へ出てよい) |
| 左右 | 帯のうち、少なくとも48画素が、使える範囲の中に残る(帯が48画素より短ければ、帯の全体) |

800x600の画面で、外形が320x264のウィンドウなら、外形の左上は、横が-272〜752、縦が0〜576の範囲に収まります。
限りに当たっても、ポインターが戻れば、また付いてきます。

クライアントから頼まれる移動(xdg_toplevelの `move`)も、受けます。

- 受けるのは、そのクライアントの中身の上でボタンが押されている間の頼みだけです(頼みに付いてくる通し番号が、いま押されているボタンのものであることを確かめます)。それ以外の頼みは、何もせずに捨てます。
- 受けると、そのボタンを離すまで、帯を掴んだときと同じに動かします。遊びは置かず、ボタンを押した点からのずれのぶんだけ動かします。画面の外の限りも、同じです。
- 受けた後、ボタンを離すまでのポインターの知らせは、クライアントには渡しません。

## 閉じる

帯の右の端に、閉じるボタンがあります。

- 大きさは24x24画素(帯と同じ高さの正方形)で、帯の右の端と上の端に、ぴったり付いています。
- 見た目は「×」の印です。フォントが無くても出るように、文字ではなく、線で描いています(10x10画素、太さ2画素)。色は、題名と同じです。
- ポインターを乗せると、ボタンの地が赤(`#c42b1c`)に、印が白(`#ffffff`)になります。
- 左のボタンで押して、そのボタンの上で離すと、クライアントに、閉じるように頼みます(xdg_toplevelの `close`)。
- 押したまま外へ出すと、地の色が元に戻ります。そのまま外で離すと、取り消しです。離す前に戻せば、また赤になり、閉じられます。
- 押した時点で、そのウィンドウは手前に出ます。奥のウィンドウの閉じるボタンも、見えていれば、1回の操作で効きます。
  手前のウィンドウに隠れているボタンには、当たりません。
- 閉じるボタンを押している間は、ウィンドウは動きません。
- 頼むだけなので、応じるかどうかは、クライアントしだいです。応じないクライアントのウィンドウは、そのまま残ります。もう一度押せば、もう一度頼みます。
  応じないクライアントを、強制的に切る仕組みは、ありません。

最大化、最小化、全画面は、できません。

- そのためのボタンは、ありません。帯をダブルクリックしても、2回押したのと同じで、何も起きません。
- クライアントには、xdg_toplevelの `wm_capabilities` で、できることの並びを空にして伝えています(版5以上の `xdg_wm_base` を使うクライアントに届きます)。

## 選ばれているウィンドウ(activated)

いちばん手前のウィンドウが、「選ばれている」ウィンドウです。クライアントには、xdg_toplevelの `activated` の状態として、configureで知らせます。

- `activated` が付くのは、いつも、いちばん手前の1つだけです。
- 新しいウィンドウをつないだとき:新しいウィンドウに付き、前に手前だったものからは外れます。新しいウィンドウには、最初のconfigureで一緒に知らせます。
- クリックで手前に出したとき:出したウィンドウに付き、前に手前だったものからは外れます。
- いちばん手前のウィンドウが去ったとき:その下にあったものに付きます。
- 奥のウィンドウが去ったとき:何も変わりません。
- 知らせるのは、状態が変わったウィンドウにだけです。変わらないウィンドウには、configureを送りません。

キーボードの入力と、キーボードのフォーカスは、まだ扱っていません。`activated` は、見た目を変えたいクライアントのための知らせです。
Seinasが描く題名の帯も、選ばれているウィンドウだけ、色が違います。

## 置き方

置き場所には、0から順に番号が付いています。置き場所は、題名の帯を含めた外形の左上の位置です。
中身は、そこから帯の高さ(24画素)だけ下に来ます。
位置は、使える範囲(上の「layer surface と使える範囲」)の左上を基準にします。exclusive zone を持つ layer surface が無ければ、画面の左上です。

| 番号 | 外形の左上の位置(使える範囲の左上からのずれ。画素) |
| --- | --- |
| 0 | (0, 0) |
| 1 | (32, 32) |
| 2 | (64, 64) |
| n | (32 × n, 32 × n) |

- 新しいウィンドウは、空いている中で、いちばん小さい番号の置き場所に入ります。
  1つ目は左上、2つ目はそこから右と下へ32画素ずつずれた所、という並びになります。
- ウィンドウが去ると、その番号は空きます。次のウィンドウは、空いた番号に入ります。
  たとえば、ウィンドウが1つだけのときは、何度つなぎ直しても左上に出ます。
- 置いたウィンドウの位置は、動かされるまで変わりません。
- 動かしたウィンドウは、置き場所の番号を手放します。その番号は空き、次の新しいウィンドウが使えます。
  動かしたウィンドウの位置は、そのウィンドウが去るまで保ちます。
- 帯を押しただけ(4画素の遊びの中で離した)のウィンドウは、動いていないので、番号を持ったままです。
- 少しだけ動かしたウィンドウの上に、新しいウィンドウが重なることがあります。空いている所を探して置くことは、していません。
- ずらす量(32画素)は、帯の高さ(24画素)より大きくしてあります。奥のウィンドウの帯は、手前のウィンドウに隠れず、題名の頭の部分が読めます。

## 折り返し

置き場所の数には、限りがあります。外形の左上が、使える範囲の短い辺の半分を超えないように決めています。

- 置き場所の数は「短い辺 ÷ 2 ÷ 32」(端数は切り捨て。少なくとも1つ)です。
  800x600なら9つ(最後は(256, 256))、640x480なら7つ(最後は(192, 192))です。
- 置き場所が全部ふさがっているときは、番号0から順に、もう一度使います(すでにあるウィンドウと同じ位置に、手前に重なります)。
- ウィンドウの大きさは、置き場所を決めるときには見ていません。大きなウィンドウは、画面の右や下にはみ出すことがあります。はみ出した分は、描かれません。
- 帯は、いつも外形のいちばん上にあるので、どの置き場所でも、帯の全体が画面の中に入ります(幅が画面より広いウィンドウを除く)。

## 大きさ

クライアントには、中身に使える大きさとして、使える範囲の大きさから帯の高さを引いたものを伝えています(configure)。
exclusive zone が無ければ、800x600なら800x576、640x480なら640x456です。下に高さ 40 のタスクバーがあれば、640x480なら640x416です。それに従うかどうかは、クライアントしだいです。
zeyes-minは従わず、いつも320x240で描きます(外形は320x264)。

## ポインター(入れ子の構成)

入れ子の構成では、ポインターの下にある、いちばん手前のウィンドウへ、ポインターの動きを渡します。
座標は、そのウィンドウの中身の左上を原点にして渡します。どのウィンドウの上でもなければ、どこにも渡しません。
ポインターが題名の帯の上にあるときも、どこにも渡しません(帯はSeinasのものです)。
中身の上でボタンを押している間は、ポインターが外へ出ても、離すまで、そのウィンドウへ渡し続けます。
ウィンドウを動かしている間と、閉じるボタンを押している間は、どこにも渡しません。

受け口とfbdevの構成は、入力の装置を扱いません。試験のための入力の口(`--test-input`。`standalone.md`)を開いたときだけ、同じ決まりで働きます。

## 試験

- 置き場所の番号の決め方と折り返し、押した所のウィンドウの選び方、手前に出したときの順と置き場所、`activated` が手前の1つだけに付くことは、`crates/seinas-frontend` の単体試験(`src/stack.rs`)で確かめています。
- `activated` の知らせが実際に届くことは、`crates/seinas-standalone/tests/activation.rs` が確かめます。試験用のクライアント(`test-client window`)が、届いたconfigureの中身を書き出し、それを読みます。
- 実際の重なり方と位置は、`crates/seinas-standalone/tests/stacking.rs` が、色の違う2つのzeyes-minを偽の画面につないで、画素で確かめます。
  zeyes-minの目のまわりの色は、引数 `--skin RRGGBB` か、環境変数 `ZEYES_SKIN` で変えられます(既定は緑)。
  あわせて、帯の色が、手前のウィンドウと奥のウィンドウとで違うことも確かめます。
- 題名の帯は、`crates/seinas-standalone/tests/title.rs` が、画素で確かめます。確かめるのは、帯があること、題名の位置に文字の画素があること、題名を変えると描き直されること、選ばれているかどうかで帯の色が違うこと、題名が無いときの表示、長い題名を切ること、控えのフォントでの表示、どのフォントにも無い文字の枠、フォントが無い・壊れているときに止まらないこと、xdg-decorationの答えです。
  試験用のクライアントは、`test-client window --title TEXT` で題名を、`--app-id TEXT` でapp_idを付けられます。標準入力へ `title TEXT` の行を送ると、題名を変えます。
- 題名に出す文字の選び方と、外形の計算は、`crates/seinas-frontend` の単体試験(`src/decoration.rs`)で確かめています。文字を描く部分は、`crates/seinas-text` の試験(`tests/draw.rs`)で確かめています。
- 動かす・閉じるの決まり(動き始めの遊び、画面の外の限り、番号の扱い、閉じるボタンの当たりと取り消し、奥のウィンドウのボタン、クライアントから頼まれる移動)は、`crates/seinas-frontend` の単体試験(`src/interaction.rs`、`src/decoration.rs`、`src/stack.rs`)で確かめています。
- 実際に画面の上で動くこと、閉じるように頼む知らせがクライアントに届くことは、`crates/seinas-standalone/tests/move_close.rs` が、画素と、試験用のクライアントの出力で確かめます。ポインターの知らせは、試験のための入力の口から送ります。
  試験用のクライアントは、`--pointer` でポインターの知らせを書き出し、`--move-on-press` で移動を頼み、`--ignore-close` で閉じる頼みに応じなくなります。
- layer surface と使える範囲は、`crates/seinas-standalone/tests/layers.rs` が確かめます(ふだんのソケットに layer-shell が見えないこと、exclusive zone で使える範囲が狭まり、元に戻ること、configure の大きさ、ドラッグの限り、top の layer surface の上でのボタンがウィンドウを raise しないこと)。layer surface は、試験用のクライアント(`test-client layer`)で出します。
- 層の重なりの描画は、正解データ(`crates/seinas-standalone/tests/golden_layers.rs`)と比べます(`docs/golden.md`)。
- ウィンドウの一覧と操作は、`crates/seinas-standalone/tests/foreign_toplevels.rs` が、テスト用のクライアント(`test-client toplevels`)の出力とピクセルで確かめます(ふだんのソケットに 2 つの global が見えないこと、一覧の内容と変化、bind する前からあるウィンドウ、wl_output を後から bind したときの output_enter、activate で raise されること、close の頼み、最大化などの頼みで何も変わらないこと、負の rectangle のエラー、stop)。
- スロットの計算と、使える範囲が変わったときのウィンドウの移り方は、`crates/seinas-frontend` のユニットテスト(`src/stack.rs`)で確かめています。
- これらの試験は、`tools/fetch-fonts.sh` が置いたフォントを使います。先に、このスクリプトを実行しておいてください。

## まだ無いもの

キーボードの入力とフォーカスは、ありません。
ウィンドウの大きさを変えること、最大化、最小化、全画面は、できません。
応じないクライアントを見分けて、強制的に切る仕組みは、ありません。
クライアントが決めたウィンドウの範囲(xdg_surfaceの `set_window_geometry`)は、見ていません。自分で影を描くクライアントでは、影の外側に帯が付きます。
