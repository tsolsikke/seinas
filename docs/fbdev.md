# fbdevの裏側

`crates/seinas-fbdev` は、共通の描画(`seinas-render`)の結果を、Linuxのfbdev(`/dev/fb0`)の形の画面へ出す裏側です。
Waylandのソケットは開きません。今は、決まった絵を指定した時間だけ表示して終わる、確かめ用の実行ファイルになっています。

## 構成

| 場所 | 役割 |
| --- | --- |
| `src/layout.rs` | 画面の形式を確かめ、描画結果をその形式に直して写す |
| `src/device.rs` | 装置を開き、画面の情報を読み、画面の領域を対応づける |
| `src/present.rs` | 書いた絵を画面へ反映する処理(差し替えられる) |
| `src/picture.rs` | 確かめやすい、決まった絵 |
| `src/main.rs` | 引数を読み、絵を出して、後片付けをする |

依存は、`seinas-render` と、OSの呼び出しのための `libc` の2つだけです。wayland系のクレートは入りません。

## 動かし方

```bash
cargo run --locked -p seinas-fbdev -- --hold-ms 3000
```

| 引数 | 意味 |
| --- | --- |
| `--device PATH` | 装置のパス。無ければ環境変数 `SEINAS_FBDEV`、それも無ければ `/dev/fb0` |
| `--hold-ms N` | 絵を表示しておく時間(ミリ秒)。既定は3000 |
| `--dry-run` | 装置を開かず、メモリー上の偽の画面へ描いて、中身の要約を出す |
| `--size WIDTHxHEIGHT` | `--dry-run` のときの画面の大きさ。既定は800x600 |
| `--dump FILE` | `--dry-run` で描いた絵を、PPM形式の画像としてファイルに書く |

装置の無い環境(WSLなど)では、`--dry-run` で描くところまでを確かめられます。

```bash
cargo run --locked -p seinas-fbdev -- --dry-run --dump picture.ppm
```

## 装置の開き方

LinuxのfbdevのABI(`linux/fb.h`)に従います。

1. 装置を読み書きで開く。
2. `FBIOGET_VSCREENINFO`(0x4600)で、解像度、1画素のビット数、色の位置、見えている範囲の位置を読む。
3. `FBIOGET_FSCREENINFO`(0x4602)で、1行のバイト数(`line_length`)と、画面の領域の大きさ(`smem_len`)を読む。
4. 画面の領域の全体を、`mmap` で共有として対応づける。

画面の設定は、読むだけで変えません。

## 形式の吸収

共通の描画が返す形式は、`Xrgb8888`(メモリー上でB、G、R、Xの順)の1種類だけです。
画面の側の違いは、すべて `layout.rs` で吸収します。共通の描画には、画面の形式による分岐を入れていません。

| 違い | 吸収のしかた |
| --- | --- |
| 色の位置(赤・緑・青のビットの位置) | 1画素の中のバイトの位置に直し、画素ごとに並べ替えて書く。共通の描画と同じ並びなら、行ごとにそのまま写す |
| 1行のバイト数(`line_length`) | 行の始まりを `line_length` で数える。行の余りには触れない |
| 見えている範囲の位置(`xoffset`、`yoffset`) | 書き始める位置をずらす。範囲の外には触れない |
| 透明度のある画面 | 透明度のバイトに、不透明(0xff)を書く |

対応しない形式は、名前のある失敗で断ります。

| 失敗 | 断る条件 |
| --- | --- |
| `UnsupportedDepth` | 1画素が32ビットでない |
| `UnsupportedChannel` | 色が8ビットでない、またはバイトの境目にそろっていない |
| `OverlappingChannels` | 2つの色が同じ位置を使っている |
| `LineTooShort` | 1行のバイト数が、幅×4より小さい |
| `ScreenTooSmall` | 画面の領域が、見えている範囲を収めるには小さい |
| `InvalidSize` | 幅か高さが0、または大きすぎる |
| `SizeMismatch` | 描画結果の大きさが、画面と合わない |

## 画面への反映

画面の領域へ書いた後に何が要るかは、OSによって違います。その違いは `Presenter` という口に閉じ込めています。

- 1枚ぶんを書き終えるたびに、`Presenter::present` が、開いている装置を受け取って呼ばれます。
- Linux向けの `WriteThrough` は、何もしません。Linuxのfbdevは、書けばそのまま映るからです。
- 別のOS向けには、`Presenter` を実装した型を足して、`main.rs` で選ぶものを差し替えます。ほかの部分は変えずに済みます。

## 描く絵

画面の写しを見て、向き、色の並び、端の位置を確かめられる絵です。

- 背景は、共通の描画の背景色(暗い青)。
- 枠は、画面の端にぴったり沿った白い線。端が欠けていないかが分かります。
- 四隅の印は、左上が赤、右上が緑、左下が青、右下が黄。上下左右の向きと、色の並びが分かります。
- 中央に、白い四角。

800x600のときは、枠の太さが4画素、印の1辺が60画素です。

## 終わるときの後片付け

- 始める前に、画面の領域の中身を覚えておきます。
- 表示の時間が過ぎたら、覚えておいた中身を書き戻し、もう一度 `Presenter::present` を呼びます。
- その後、対応づけを外し、装置を閉じます。

していないこと:

- コンソールの切り替え(文字の画面を止める設定)はしません。Linuxの文字のコンソールの上で動かすと、表示の途中でコンソールの文字が上書きされることがあります。
- シグナルは受けていません。表示の途中でCtrl+Cなどで止めると、書き戻しは行われず、絵が画面に残ります。
- 覚えておく分として、画面の領域と同じ大きさのメモリーを使います。

## 確かめ方

| 確かめること | やり方 |
| --- | --- |
| 形式の吸収 | `cargo test -p seinas-fbdev`。偽の画面(1行が幅×4より長いもの、色の並びが違うもの、透明度のあるもの、見えている範囲がずれたもの)へ描いて、画素を比べる |
| ABIの構造体 | 同じテストの中で、大きさと要所の位置を `linux/fb.h` と比べる |
| 受け口が入っていないこと | `tools/check-no-wayland.sh seinas-fbdev <実行ファイル>`。依存にwayland系が無いこと、共有メモリーの実装が入っていないことを確かめる |
| スレッドとソケットを使わないこと | `strace -f` で `--dry-run` を動かし、`clone` と `socket`・`bind`・`connect`・`listen` が0回であることを見る |

実際の装置(`/dev/fb0`)への表示は、装置のある環境でしか確かめられません。

受け口を含めずに作るには、`cargo build -p seinas-fbdev` のように、このクレートだけを対象にしてください。
ワークスペース全体を一度にビルドすると、Cargoが機能を1つにまとめて、Smithayの受け口の部分までビルドに入ります。
