# 文字を描く手段の比べ

Seinasが自分で描く文字(ウィンドウの題名など)に使う、文字を描く手段(Rustのクレート)を、実際に試して比べた記録です。
どれを採るかは、まだ決めていません。この文書は、決めるための材料です。Seinasの本体には、まだ何も組み込んでいません。

調べたのは2026-10-04で、Rust 1.97.1、Linuxのx86-64です。

## 前提

- 既定のフォントは、UIがBIZ UDPゴシック、端末・コードがBIZ UDゴシック、足りない文字の最後の控えがGNU Unifont JPです。
- BIZは、OFLで公開されている版(googlefonts/morisawa-biz-ud-gothic)のRegularを使います。
- フォントは実行ファイルに埋め込まず、別のファイルとして明示的に読みます。システムのフォントの探索には頼りません。

## 試した候補

| 候補 | 版 | どういうものか |
| --- | --- | --- |
| cosmic-text + swash | cosmic-text 0.19.0(機能は `std` と `swash` だけ。`fontconfig` は外す) | 文字の並べ方(シェーピング)、行の組み方、フォントの切り替え(控え)、字形を描くことと覚えておくことを、まとめて持つ |
| swashだけ | swash 0.2.10 | シェーピングと、字形を描くこと(ヒンティング付き)を持つ。行の組み方と控えへの切り替えは、自分で書く |
| fontdue | fontdue 0.9.4 | 字形を描くだけの、小さなクレート。シェーピングはしない |

どの候補も、同じ文字列を、同じフォントのファイルから描き、Xrgb8888の画素(pixmanで合成できる形)に出しています。
試しのコードは `trials/text/` にあります。本体のワークスペースとは別で、依存も `Cargo.lock` も分けてあります。

## 試して分かったこと

### 12px前後で、字形のヒンティングを入れると「8」が「0」に見える

cosmic-textとswashは、フォントに入っているヒンティングの命令(小さい字を画素の格子に合わせる処理)を実行できます。
ところが、BIZ UDゴシック・BIZ UDPゴシックで、これを入れると、13px以下で、数字の「8」の真ん中の横線が消えて、「0」のように見えることがあります(「0123456789」が「0123456709」に、「¥1,980」が「¥1,900」に見える)。
12pxでは、cosmic-textでもswashでも起きました。10〜13pxのほかの大きさでは、字形を置く位置によって、出たり出なかったりします。14px以上では、見られませんでした。
ヒンティングを切ると、どの大きさでも「8」と読めます。

- ヒンティングを入れると、線がくっきりします。切ると、線が少しぼやけますが、形は正しく出ます。
- fontdueは、もともとヒンティングをしないので、この問題は起きません。
- 見比べ用の画像には、ヒンティングを入れたものと切ったものの両方を並べてあります。

読み間違いは困るので、少なくとも13px以下では、ヒンティングを切るのがよいと考えます。大きさに関わらず切る、という選び方もあります(見た目がそろう)。

### cosmic-textで、字形の位置を画素に合わせる設定にすると、奇数のpxで半角と全角の幅が崩れる

cosmic-textには、字形の位置を整数の画素に合わせる設定(`Hinting::Enabled`)があります(上のヒンティングとは別の設定です)。
これを入れると、字形ごとに幅が切り上げられます。BIZ UDゴシックの13pxでは、半角が6.5pxから7pxになり、半角8文字が56px、全角4文字が52pxで、1:2でなくなります。
偶数のpx(12、14、16、18)では、半角の幅がもともと整数なので、崩れません。

- 端末用のフォントでは、この設定を入れないか、文字の升目の位置を自分で決めて1文字ずつ描く、のどちらかが要ります。
- 試しのコードでは、UI用のフォントにだけ入れています。

### BIZに無い文字がある

試した文字列のうち、二重線の罫線(═ U+2550、║ U+2551、╬ U+256C)は、BIZ UDゴシックにもBIZ UDPゴシックにも字形がありません(豆腐になります)。
細い罫線(─│┌┐└┘├┤┬┴┼)と太い罫線(━┃╋)は、あります。
控えのフォントが要る、ということの実例です。

cosmic-textで、一覧にもう1つフォントを足して試したところ(手元にあったDejaVu Sans Monoで代用)、無い文字だけが、そのフォントから描かれました。
`trials/text/` の `try-cosmic` は、4つ目の引数でフォントを1つ足せます。GNU Unifont JPを取得した後に、同じやり方で試せます。

### そのほか

- 円記号(¥ U+00A5)とバックスラッシュ(\ U+005C)は、別の字形で描かれます。バックスラッシュが円記号になることは、ありません。
- BIZ UDゴシックの「O」と「0」は、形が近いです(0に斜線や点はありません)。「I」「l」「1」は、見分けられます。これは、フォントの性質です。
- どちらのフォントにも、文字ごとの位置の調整の表(GPOSとkern)と、埋め込みのビットマップは、入っていません。入っているのは、字形の置き換えの表(GSUB)と、ヒンティングの命令です。
- fontdueは、読み込むときに全部の字形を下ごしらえします。BIZは字形が多いので、フォント2つで130 MBを使いました。

## 推す案

cosmic-text + swash を推します。使い方は、次のとおりです。

- 機能は `std` と `swash` だけにして、`fontconfig` は外す(システムのフォントを読まない)。
- フォントは、ファイルから読んで、使うものだけを一覧に入れて渡す。ロケールは `ja-JP` を明示する。
- 控えは、一覧にGNU Unifont JPを足し、控えの名前の並びを自分で決めて渡す(`Fallback` を実装して、`FontSystem::new_with_locale_and_db_and_fallback` に渡す)。
- 字形のヒンティングは、少なくとも13px以下では切る。
- 端末用では、字形の位置を画素に合わせる設定を入れない(または、升目の位置を自分で決める)。

理由:

- 控えのフォントへの切り替えを、自分で書かずに済みます。BIZに無い文字が実際にあるので、この仕組みは必ず要ります。
- 結合濁点が、合成済みの文字と同じに描けます。
- 和欧が混ざった行を、文字の種類ごとに区切って並べる処理を、持っています。
- Cのライブラリを使わないので、muslの静的ビルドに、そのまま入ります。FreeTypeやHarfBuzzを作る手順は、要りません。
- フォントとロケールを、明示的に渡せます。
- 依存のライセンスは、どれもMIT・Apache-2.0・Zlibのどれかで使えます。

弱い点:

- 実行ファイルが、3 MBほど大きくなります(stripして2.5 MB)。今のseinas-standalone(muslの静的版で3.9 MB)に対して、小さくありません。
- 依存のクレートが34あります。
- 速さは、3つの中でいちばん遅いです。ただし、1枚(411文字)で0.5ミリ秒なので、題名を描く程度なら、問題になりません。

ほかの候補について:

- swashだけ:大きさは3分の2(+1.9 MB)、依存は8つで済み、描いた字形はcosmic-textと同じです(cosmic-textも、字形を描くのにswashを使っています)。ただし、控えへの切り替え、文字の種類ごとの区切り、行の折り返しを、自分で書くことになります。題名のような1行だけを描くなら足りますが、後で端末や入力欄を作るときに、書く量が増えます。大きさを優先するなら、こちらが次の案です。
- fontdue:いちばん小さく、速いです。しかし、BIZを読むだけで130 MBを使うこと、結合濁点を合成しないこと、控えの仕組みが無いことから、今回の用途には向きません。

## 見比べ用の画像

`trials/text/out/` に出ます(リポジトリには入れていません)。作り方は、次のとおりです。

```bash
tools/fetch-fonts.sh
```

```bash
trials/text/run.sh
```

| ファイル | 中身 |
| --- | --- |
| `compare-<フォント>-<配色>-<大きさ>px.png` | 同じ条件で、候補を上から順に並べたもの。上から、cosmic-text、cosmic-text(ヒンティングなし)、swash、swash(ヒンティングなし)、fontdue |
| `compare-sizes-<フォント>-<配色>.png` | 10〜20pxを1pxずつ変えて、見分けにくい字を並べたもの。並びは同じ |
| `<候補>-<フォント>-<配色>.png` | 1つの候補を、12・14・16・18pxの順に並べたもの |
| `<候補>-report.txt` | 速さ、メモリー、文字の幅の記録 |

フォントは `udp`(BIZ UDPゴシック)と `ud`(BIZ UDゴシック)、配色は `light`(明るい背景)と `dark`(暗い背景)です。
