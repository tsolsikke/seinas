# 文字の描き方

Seinasが自分で描く文字(ウィンドウの題名など)の、描き方の決まりと、手段を選ぶために比べた記録です。

- 前半(「決まったこと」「本体への組み込み」)は、今のSeinasの決まりです。
- 後半(「手段の比べ」から後)は、文字を描く手段(Rustのクレート)を実際に試して比べた記録です。調べたのは2026-10-04で、Rust 1.97.1、Linuxのx86-64です。比べたときは、まだ何も決まっていなかったので、その時点の書き方のまま残しています。

## 決まったこと

比べた結果を受けて、2026-10-04に次のように決まりました。

| 項目 | 決まり |
| --- | --- |
| 描く手段 | cosmic-text + swash。機能は `std` と `swash` だけにして、`fontconfig` は外す(システムのフォントを探さない) |
| フォントの渡し方 | ファイルから読み、使うものだけを一覧に入れる。ロケールは `ja-JP` を明示する |
| UIのフォント | BIZ UDPゴシック Regular(OFLで公開されている版 v1.051。手を加えない) |
| 控えのフォント | GNU Unifont JP 18.0.01(OFL 1.1を選んで使う)。UIのフォントに無い文字を描く |
| 文字の大きさ | 14画素以上。既定は14画素。13画素以下は、既定では使わない |
| 字形のヒンティング | 14画素以上で入れ、13画素以下では切る(12画素前後で入れると、「8」が「0」に見えるため) |
| フォントの置き方 | 実行ファイルに埋め込まず、別のファイルとして明示的に読む。リポジトリにも入れない |
| 端末・コード用(まだ使っていない) | BIZ UDゴシック Regular。字形の位置を画素に合わせる設定(`Hinting::Enabled`)は使わず、升目の位置をSeinasの側で決める(奇数の大きさで、半角と全角の幅が1:2でなくなるため) |

実行ファイルが3 MBほど大きくなることは、受け入れています。

## 本体への組み込み

文字を描く部分は、`crates/seinas-text` に分けてあります。今、これを使っているのは、ウィンドウの題名の帯だけです(`docs/window-placement.md`)。

### クレートの分け方

| クレート | 文字を描くか | 依存 |
| --- | --- | --- |
| `seinas-text` | 描く | cosmic-text(swash、fontdbなど)。Waylandにも、Smithayにも、pixmanにも依存しない |
| `seinas-frontend` | 題名の帯を描くのに `seinas-text` を使う | Smithay、`seinas-text` |
| `seinas`、`seinas-standalone` | 受け口を通じて使う | 上の2つ |
| `seinas-render`、`seinas-fbdev` | 描かない | `seinas-text` も、cosmic-textも、依存に入らない |

文字を描かない構成に、文字を描くクレートが入っていないことは、次で確かめます。CIにも入れてあります。

```bash
tools/check-deps.sh seinas-fbdev seinas-text cosmic-text swash fontdb
```

```bash
tools/check-deps.sh seinas-render seinas-text cosmic-text swash fontdb
```

`seinas-text` は、呼ぶ側が用意した画素(1画素4バイト、並びは B, G, R, X)の上に、1行の文字を重ねて描きます。
描く先がどこか(pixmanの画像か、ほかの何かか)は知りません。

### フォントの置き場

フォントは、決まった名前のファイルとして、1つのディレクトリに置きます。

| ファイル | 中身 |
| --- | --- |
| `BIZUDPGothic-Regular.ttf` | UIのフォント(BIZ UDPゴシック) |
| `unifont_jp-18.0.01.otf` | 控えのフォント(GNU Unifont JP) |

置き場は、次の順で決まります。

1. 引数 `--fonts DIR`(`seinas` と `seinas-standalone`)
2. 環境変数 `SEINAS_FONTS`
3. どちらも無ければ `target/fonts`(作業中のディレクトリから見た位置。`tools/fetch-fonts.sh` が置く、開発用の場所)

ZeikOSの上での置き場は、まだ決めていません。決まったら、引数か環境変数で渡します。

### フォントが読めないとき

Seinasは、フォントが読めなくても止まりません。原因は、起動のときにログ(標準エラー)へ出します。

| 状態 | 動き |
| --- | --- |
| 両方とも読める | UIのフォントで描き、無い文字は控えで描く |
| UIのフォントだけ読めない(無い、壊れている、別のフォントである) | 控えのフォントで、全部の文字を描く |
| 控えのフォントだけ読めない | UIのフォントで描く。UIのフォントに無い文字は、四角の枠になる |
| 両方とも読めない | 文字を描かない(題名の帯は、帯だけになる) |

ファイルの中身は、フォントの名前(`BIZ UDPGothic`、`Unifont-JP`)で確かめています。名前が合わないファイルは、使いません。

### 無い文字

- UIのフォントに無い文字は、控えのフォントで描きます。たとえば、罫線の「═」(U+2550)は、BIZ UDPゴシックに無く、GNU Unifont JPにあります。
- どちらのフォントにも無い文字は、四角の枠で描きます。フォントが持っている「無い字」の形はフォントごとに違うので、枠はSeinasが自分で描いています。
- GNU Unifont JP(`unifont_jp`)が持っているのは、基本多言語面(U+0000〜U+FFFF)の文字です。それより上の文字(絵文字の多く、一部の漢字)は、今は枠になります。
- 改行などの制御文字は、空白として扱います。題名は、いつも1行です。

### 長い行

使ってよい幅に収まらない行は、末尾を切って「…」を付けます。「…」を足した後の幅が、収まるようにします。
切る場所は、字形のまとまり(濁点の付いた字などが、途中で切れない単位)の境目です。

### 試験

- `crates/seinas-text/tests/draw.rs`:1行を描けること、長い行を切ること、控えのフォントに切り替わること、どのフォントにも無い文字が枠になること、フォントが無い・壊れているときに落ちないこと。

### まだ無いもの

- 題名のほかの文字(端末、入力欄など)は、まだ描いていません。BIZ UDゴシックも、まだ読んでいません。
- 文字の大きさや色を、設定で変える仕組みはありません。
- 絵文字など、基本多言語面より上の文字のための控えは、入れていません。

## 手段の比べ

ここから後は、手段を選ぶために比べたときの記録です。

## 前提

- 既定のフォントは、UIがBIZ UDPゴシック、端末・コードがBIZ UDゴシック、足りない文字の最後の控えがGNU Unifont JPです。
- BIZは、OFLで公開されている版(googlefonts/morisawa-biz-ud-gothic)のRegularを使います。
- フォントは実行ファイルに埋め込まず、別のファイルとして明示的に読みます。システムのフォントの探索には頼りません。

## 試した候補

| 候補 | 版 | どういうものか |
| --- | --- | --- |
| cosmic-text + swash | cosmic-text 0.19.0(機能は `std` と `swash` だけ。`fontconfig` は外す) | 文字の並べ方(シェーピング)、行の組み方、フォントの切り替え(控え)、字形を描くことと覚えておくことを、まとめて持つ |
| swashだけ | swash 0.2.10 | シェーピングと、字形を描くこと(ヒンティング付き)を持つ。行の組み方と控えへの切り替えは、自分で書く |

## 試して分かったこと

### 12px前後で、字形のヒンティングを入れると「8」が「0」に見える

cosmic-textとswashは、フォントに入っているヒンティングの命令(小さい字を画素の格子に合わせる処理)を実行できます。
ところが、BIZ UDゴシック・BIZ UDPゴシックで、これを入れると、13px以下で、数字の「8」の真ん中の横線が消えて、「0」のように見えることがあります(「0123456789」が「0123456709」に、「¥1,980」が「¥1,900」に見える)。
12pxでは、cosmic-textでもswashでも起きました。10〜13pxのほかの大きさでは、字形を置く位置によって、出たり出なかったりします。14px以上では、見られませんでした。
ヒンティングを切ると、どの大きさでも「8」と読めます。

- ヒンティングを入れると、線がくっきりします。切ると、線が少しぼやけますが、形は正しく出ます。
- fontdueは、もともとヒンティングをしないので、この問題は起きません。
- 見比べ用の画像には、ヒンティングを入れたものと切ったものの両方を並べてあります。

読み間違いは困るので、少なくとも13px以下では、ヒンティングを切るのがよいと考えます。大きさに関わらず切る、という選び方もあります(見た目がそろう)。

### cosmic-textで、字形の位置を画素に合わせる設定にすると、奇数のpxで半角と全角の幅が崩れる

cosmic-textには、字形の位置を整数の画素に合わせる設定(`Hinting::Enabled`)があります(上のヒンティングとは別の設定です)。
これを入れると、字形ごとに幅が切り上げられます。BIZ UDゴシックの13pxでは、半角が6.5pxから7pxになり、半角8文字が56px、全角4文字が52pxで、1:2でなくなります。
偶数のpx(12、14、16、18)では、半角の幅がもともと整数なので、崩れません。

- 端末用のフォントでは、この設定を入れないか、文字の升目の位置を自分で決めて1文字ずつ描く、のどちらかが要ります。
- 試しのコードでは、UI用のフォントにだけ入れています。

### BIZに無い文字がある

試した文字列のうち、二重線の罫線(═ U+2550、║ U+2551、╬ U+256C)は、BIZ UDゴシックにもBIZ UDPゴシックにも字形がありません(豆腐になります)。
細い罫線(─│┌┐└┘├┤┬┴┼)と太い罫線(━┃╋)は、あります。
控えのフォントが要る、ということの実例です。

cosmic-textで、一覧にもう1つフォントを足して試したところ(手元にあったDejaVu Sans Monoで代用)、無い文字だけが、そのフォントから描かれました。
`trials/text/` の `try-cosmic` は、4つ目の引数でフォントを1つ足せます。GNU Unifont JPを取得した後に、同じやり方で試せます。

### そのほか

- 円記号(¥ U+00A5)とバックスラッシュ(\ U+005C)は、別の字形で描かれます。バックスラッシュが円記号になることは、ありません。
- BIZ UDゴシックの「O」と「0」は、形が近いです(0に斜線や点はありません)。「I」「l」「1」は、見分けられます。これは、フォントの性質です。
- どちらのフォントにも、文字ごとの位置の調整の表(GPOSとkern)と、埋め込みのビットマップは、入っていません。入っているのは、字形の置き換えの表(GSUB)と、ヒンティングの命令です。
- fontdueは、読み込むときに全部の字形を下ごしらえします。BIZは字形が多いので、フォント2つで130 MBを使いました。

## 推す案

(この案が、そのまま採られました。上の「決まったこと」を見てください。)

cosmic-text + swash を推します。使い方は、次のとおりです。

- 機能は `std` と `swash` だけにして、`fontconfig` は外す(システムのフォントを読まない)。
- フォントは、ファイルから読んで、使うものだけを一覧に入れて渡す。ロケールは `ja-JP` を明示する。
- 控えは、一覧にGNU Unifont JPを足し、控えの名前の並びを自分で決めて渡す(`Fallback` を実装して、`FontSystem::new_with_locale_and_db_and_fallback` に渡す)。
- 字形のヒンティングは、少なくとも13px以下では切る。
- 端末用では、字形の位置を画素に合わせる設定を入れない(または、升目の位置を自分で決める)。

理由:

- 控えのフォントへの切り替えを、自分で書かずに済みます。BIZに無い文字が実際にあるので、この仕組みは必ず要ります。
- 結合濁点が、合成済みの文字と同じに描けます。
- 和欧が混ざった行を、文字の種類ごとに区切って並べる処理を、持っています。
- Cのライブラリを使わないので、muslの静的ビルドに、そのまま入ります。FreeTypeやHarfBuzzを作る手順は、要りません。
- フォントとロケールを、明示的に渡せます。
- 依存のライセンスは、どれもMIT・Apache-2.0・Zlibのどれかで使えます。

弱い点:

- 実行ファイルが、3 MBほど大きくなります(stripして2.5 MB)。今のseinas-standalone(muslの静的版で3.9 MB)に対して、小さくありません。
- 依存のクレートが34あります。
- 速さは、3つの中でいちばん遅いです。ただし、1枚(411文字)で0.5ミリ秒なので、題名を描く程度なら、問題になりません。

ほかの候補について:

- swashだけ:大きさは3分の2(+1.9 MB)、依存は8つで済み、描いた字形はcosmic-textと同じです(cosmic-textも、字形を描くのにswashを使っています)。ただし、控えへの切り替え、文字の種類ごとの区切り、行の折り返しを、自分で書くことになります。題名のような1行だけを描くなら足りますが、後で端末や入力欄を作るときに、書く量が増えます。大きさを優先するなら、こちらが次の案です。
- fontdue:いちばん小さく、速いです。しかし、BIZを読むだけで130 MBを使うこと、結合濁点を合成しないこと、控えの仕組みが無いことから、今回の用途には向きません。

`trials/text/out/` に出ます(リポジトリには入れていません)。作り方は、次のとおりです。

```

```
